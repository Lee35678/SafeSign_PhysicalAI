| 항목 | 선택 | 한 줄 이유 |
| --- | --- | --- |

| 특징 | **관절 각도·거리 23차원** (`joint23`) | 좌표를 그대로 쓰면 "엄지가 펴졌나"가 12개 성분에 흩어진다. 관절 관계량으로 바꾸면 한 축이 된다 — 실측 77.57% → **88.71%** (§2-2) |

## 1. 왜 딥러닝이 아니라 SVM인가

후보는 두 갈래였다 (`document/02_설계문서_v2.md` §2).

- **후보 A — 랜드마크 + 경량 분류기**: MediaPipe가 뽑아준 21개 좌표를 입력으로 쓰는 방식
- **후보 B — 이미지 분류(CNN fine-tuning)**: 손 영역을 잘라 CNN에 넣는 방식

**A를 골랐다.** 결정적인 이유는 네 가지다.

1. **데이터가 적다.** 클래스당 ~300장, 총 8클래스 2,400장이 목표다(04_데이터셋명세서_v2 §2).
   CNN fine-tuning에는 턱없이 부족하지만, 63차원 저차원 벡터를 쓰는 고전 분류기에는 충분한 규모다.
2. **조명·배경 강인성을 MediaPipe가 이미 해결해준다.** 우리가 픽셀을 직접 다루지 않으므로
   배경이 바뀌어도 좌표는 비슷하게 나온다. 계획서가 악조건 인식을 범위에서 제외한 것과도 맞는다.
3. **일치율(match_score)을 자연스럽게 얻는다.** 같은 63차원 공간에서 코사인 유사도만 재면 되므로,
   "얼마나 비슷한가"를 위한 별도 설계가 필요 없다(§5 참고).
4. **비전공자 팀원이 설명할 수 있어야 한다.** 팀 4명 중 2명이 비전공자이고, 5주 안에 각자 자기
   파트를 발표에서 설명해야 한다(01_프로젝트계획서_v4 정성 목표). `C`, `gamma` 두 개짜리 모델이
   "어떤 층을 얼마나 얼렸는지" 설명해야 하는 CNN보다 훨씬 유리하다.

그중에서도 **RBF 커널 SVM**을 고른 이유 (05_모델카드_v3 §5-2):

- **MLP 대비**: 소규모 데이터에서 초기화·학습률에 덜 민감하고 재현이 쉽다. 5주 일정에서 "어제는
  잘 됐는데 오늘은 안 되는" 상황을 피하는 게 중요했다.
- **랜덤포레스트 대비**: 랜덤포레스트는 축에 수직인 분할을 쌓는 방식이라, 회전 정렬까지 마친
  연속형 좌표 공간에서는 매끄러운 커널 경계를 만드는 SVM이 더 적합하다고 판단했다.
- **수신호 7종이 "손가락 조합"으로만 구분된다**(02_설계문서_v2 §4)는 점도 근거다. 미세한 질감이
  아니라 관절 위치의 기하학적 차이라서, 좌표 기반 분류기로 충분히 갈린다.

> ⚠️ **실측으로 확인된 혼동 (2026-09-20, 공개 데이터 2,708건)**: 예상대로 "손가락 한두 개 차이" 쌍이
> 가장 많이 틀렸다 — **주의(소지만) ↔ 우회전 유도(엄지+소지) 8건**, 좌회전 ↔ 우회전 6건,
> 후진 ↔ 주의 5건. 특히 첫 번째 쌍은 손모양 변경(우회전 유도 약지→소지, 04_데이터셋명세서_v2 §1)으로
> **새로 생긴** 위험이다. 정확도가 목표에 못 미치면 분류기를 더 만지기 전에 **손모양 재설계**부터
> 검토하는 게 맞다 — 모델 문제가 아니라 클래스 설계 문제이기 때문 (05_모델카드_v3 §9).

## 2. 특징 추출: 왜 이런 정규화를 거치는가

코드: [`src/cognition/normalize.py`](src/cognition/normalize.py) (05_모델카드_v3 §3-5 구현체)

MediaPipe가 주는 원본 좌표를 그대로 쓰면, 분류기가 "손 모양"이 아니라 **"손이 어디에 있었는지,
얼마나 컸는지, 어느 쪽으로 기울었는지"** 를 외워버린다. 그래서 네 가지 변인을 차례로 제거한다.

| 단계 | 하는 일 | 제거되는 변인 |
| --- | --- | --- |
| 1. 좌우 손 통일 | Handedness가 `Left`면 x좌표 반전 | 왼손/오른손 차이 — 어느 손으로 해도 같은 신호로 인정 |
| 2. 원점 이동 | 손목(landmark 0)을 원점으로 | 화면 속 손의 위치 |
| 3. 스케일 정규화 | 손목→중지 MCP 거리로 나눔 | 손 크기, 카메라와의 거리 |
| 4. 회전 정렬 | 손 고유 좌표계로 변환 | 손 기울임(촬영 변인 ±15°) |

4번은 문서가 "손목→중지 MCP 벡터를 기준 축에 정렬"이라고만 정해두었는데, 축 하나만 맞추면 **그 축을
중심으로 도는 회전(roll)이 남는다.** 그래서 구현에서는 손바닥 가로 방향(검지 MCP → 새끼 MCP)을 두 번째
기준으로 삼아 x·y·z 세 축을 모두 고정했다. 남는 자유도 없이 완전한 canonical 자세가 된다.

결과는 21 × 3 = **63차원**. 정규화 특성상 손목(0,0,0)과 중지 MCP(0,1,0)는 항상 상수라 실질 정보는
57차원이지만, 문서가 정의한 63차원을 그대로 유지했다(스키마·문서와 숫자를 어긋나게 만들지 않기 위함).

> **학습과 추론이 같은 코드를 쓴다.** 로컬 학습 스크립트는 `src/`를 `sys.path`에 넣어 이
> `normalize.py`를 그대로 import하고, Colab 노트북은 저장소를 `git clone` 해서 같은 파일을 쓴다.
> 전처리가 학습 때와 추론 때 달라지는 것(train-serve skew)은 조용히 정확도를 갉아먹는 대표적인
> 사고 유형이라, 아예 복붙 대신 같은 파일을 쓰도록 구조를 잡았다.

### 2-1. 손 방향 축 — 4번에서 버린 정보를 되살리는 선택지 (2026-09-21)

위 4번 회전 정렬은 손 기울임에 강해지는 대신, **"같은 손모양을 다른 방향으로 든다"는 축을 통째로
버린다.** 문제는 그 축이 없으면 7종을 충분히 떼어놓을 자리가 없다는 것이다.

손모양 32가지를 전수 계산한 결과(`document/회의자료_안건3_손모양거리계산표.md`):

- 손가락 **1개 차이는 74%가 합격선 미달**. 2개 차이부터 안전
- 기존 6종이 32자리 중 **24자리를 막아** 쓸 수 있는 자리가 8개뿐이고, 전부 약지를 쓰거나 검지를 접는
  부자연스러운 모양
- 7종 **전체를 재설계해도** 최선이 0.9650인데, 클래스 내부 퍼짐(후진 하위 5% 0.9681)이 그보다 크다

즉 손모양을 어떻게 재배치해도 32자리라는 공간의 천장에 걸린다. 그래서 축을 하나 더 열기로 했다
(회의 안건 3 A안).

```python
to_feature_vector(landmarks, handedness, with_orientation=True)   # 63 + 6 = 69차원
```

| | 차원 | `feature_mode` |
| --- | --- | --- |
| 기본 | 63 | `landmark63` |
| 방향 축 사용 | **69** | `landmark63+orient6` |

추가 6차원은 **회전행렬의 앞 두 열(x축·y축)** 이다. 9개를 다 넣으면 중복이고, 오일러각은 불연속
지점이 생기며, 쿼터니언은 부호 모호성이 있다. 앞 두 열만 쓰면 z축은 외적으로 복원되므로 정보 손실
없이 연속적이다. 앞 63차원은 그대로 유지되므로 손모양 부분의 회전 불변성은 깨지지 않는다.

**🔴 기본값은 꺼짐이고, 지금 켜면 안 된다.** 공개 데이터는 클래스마다 출처 데이터셋이 달라
촬영 각도가 클래스와 상관되어 있을 수 있다(04 §3). 그 상태로 켜면 모델이 수신호가 아니라
**"어느 데이터셋 사진인가"** 를 학습한다. 카메라 1대가 고정된 현장에서는 그 단서가 사라져 성능이
무너진다 — §3의 세션 누수와 같은 종류의 함정이다.

자체 촬영 데이터(손 방향을 바꿔가며 찍은 것)를 확보한 뒤 아래처럼 A/B로 비교해서 결정한다.

```bash
python training/train_svm.py                      # 63차원
python training/train_svm.py --with-orientation   # 69차원
```

#### 공개 데이터로 미리 재본 결과 (2026-09-21, 27,735건 세션 단위 5겹)

| 클래스 | 63차원 재현율 | 69차원 재현율 | 차이 |
| --- | --- | --- | --- |
| 정지 | 99.0% | 99.0% | — |
| 서행 | 98.2% | 98.7% | +0.5%p |
| 좌회전 유도 | 97.3% | 97.5% | +0.2%p |
| **우회전 유도** | 73.7% | **78.5%** | **+4.8%p** |
| 확인 완료 | 70.0% | 71.4% | +1.4%p |
| **후진** | 44.1% | **9.3%** | **-34.8%p** |
| **주의** | 62.7% | **70.4%** | **+7.7%p** |
| **전체** | **77.57%** / F1 0.784 | **77.11%** / F1 0.736 | **-0.46%p** |

읽는 법이 중요하다.

- **겨냥한 문제는 실제로 나아진다.** 우회전 유도 +4.8%p, 주의 +7.7%p — 방향 축이 이 쌍을
  갈라놓는다는 가설 자체는 데이터가 지지한다.
- **그런데 후진이 무너진다** (44.1% → 9.3%, 대부분 확인 완료로 흘러감). 후진은 "검지만 펴기"라
  주먹과 손가락 하나 차이인데, 공개 데이터에서 이 클래스의 촬영 각도 분산이 커서 방향 6차원이
  신호가 아니라 **잡음**으로 들어간 것으로 보인다.
- 그래서 전체로는 오히려 조금 나빠진다.

**결론: 방향 축은 보류한다** (2026-09-22 확정).

자체 촬영으로 확인한 결과, **손을 좌우로 기울여도 정답률이 떨어지지 않았다**:

| 손 방향 | 시도 | 정답률 |
| --- | --- | --- |
| 정면 | 14 | 100% |
| 좌기울임 | 14 | 100% |
| 우기울임 | 7 | 100% |

회전 정렬이 방향을 지우는 것이 **오히려 강점으로 작동**하고 있다 — 학습자가 손을 어떻게 들든
같은 판정이 나온다. 방향 축을 켜야 할 근거가 없고, 켜면 후진이 무너지는 위험만 남는다.

코드는 남겨둔다(`--features landmark63+orient6`). 나중에 손 방향으로 구분해야 하는 수신호가
추가되면 그때 다시 검토한다.

## 3. 데이터 분할: 왜 인물 단위인가

04_데이터셋명세서_v2 §4가 **subject-wise split 강제**를 못 박았다. 이유는 단순하다 — 사람마다 손
모양·관절 비율·습관이 다른데, 같은 사람의 손이 train과 test에 섞이면 모델이 "이 사람의 손"을 외워서
실제보다 높은 점수가 나온다. 팀원 4명이 데이터 대부분을 찍는 구조라 위험이 특히 크다.

그래서 코드에서는 두 겹으로 지킨다.

1. **최종 test 분리**: 외부인 1~2명의 `subject_id`를 `TEST_SUBJECT_IDS`로 지정해 학습에서 완전히 제외.
2. **교차검증도 인물 단위**: 하이퍼파라미터 탐색의 CV를 `GroupKFold(groups=subject_id)`로 돌린다.
   일반 `KFold`를 쓰면 검증 점수 자체가 부풀려져 잘못된 하이퍼파라미터를 고르게 된다.

### 3-1. ⚠️ 공개 데이터에는 이 원칙을 적용할 수 없다 (2026-09-20)

현재 학습 데이터의 전부인 공개 데이터셋 27,735건은 **촬영자 정보가 없어 `subject_id`가 전부 `"public"`
하나**다. 그룹이 1개면 `GroupKFold`가 아예 성립하지 않는다(n_splits ≥ 2 필요).

더 나쁜 사실이 하나 더 있다. 공개 데이터에는 **같은 원본의 복사본과 연속 촬영 컷이 섞여 있다.**
`color_18_0002 (2).png` 같은 복사본, 같은 사람이 같은 자리에서 연달아 찍은 컷들이다. 무작위로
나누면 사실상 **같은 사진을 학습과 평가 양쪽에서 보게 된다.**

같은 모델·같은 데이터로 분할 방식만 바꿔 측정한 결과 (2026-09-21):

| 분할 | 정답률 | 무슨 뜻인가 |
| --- | --- | --- |
| 무작위 5겹 | **98.81%** | 복사본이 양쪽에 들어감 — 사실상 외운 것을 다시 묻는 것 |
| 같은 파일 복사본만 분리 | 98.88% | 거의 효과 없음 (연속 컷이 그대로 남음) |
| **세션 단위 5겹** | **77.57%** | "처음 보는 손"에 가장 가까움 |

**-21.2%p.** 전체의 97.7%가 805개 세션에 묶여 있고, 표본의 69.8%에 유사도 0.999 이상인 쌍둥이가 있다.

그래서 `train_svm.py`의 기본 분할은 **세션 단위 GroupKFold**다.

```bash
python training/train_svm.py --split session   # 기본값. 파일명에서 세션 키를 뽑아 묶는다
python training/train_svm.py --split subject   # 자체 촬영 데이터가 들어온 뒤 쓸 것
python training/train_svm.py --split random    # 비교용. 이 점수는 보고에 쓰지 않는다
```

세션 키는 파일명에서 복사본 표시 ` (2)`, 확장자, `_cropped`, `_seg_N`, 꼬리 일련번호를 떼어 만든다
(`train_svm.py::session_key`). 완벽하진 않지만 무작위보다 훨씬 정직한 하한을 준다.

**그래도 공개 데이터로 나온 정답률은 "파이프라인이 도는지" 확인용이지 성능 근거가 아니다.**
01_프로젝트계획서_v4의 KPI는 반드시 **자체 촬영한 외부인 데이터**로 측정한다 (04_데이터셋명세서_v2 §4).

### 3-2. 클래스 불균형 (18배)

공개 데이터는 정지 308장 vs 좌회전_유도 5,629장으로 최대 18배 차이 난다. 데이터가 적은 클래스를 덜
맞히게 되는데, 하필 **정지가 치명 오분류 KPI(0건) 대상**이라 그냥 두면 안 된다.

- 그리드서치에 `class_weight=[None, "balanced"]`를 넣어 불균형 보정을 후보로 둔다(§4-1).
- 더 균형을 맞추고 싶으면 데이터 쪽에서 `build_dataset.py --per-class 500` 처럼 상한을 걸어 다시 변환한다.

## 4. 학습 설정과 τ(미판정 임계값)

### 4-1. 하이퍼파라미터 탐색

```python
Pipeline([
    ("scaler", StandardScaler()),
    ("clf", CalibratedClassifierCV(SVC(kernel="rbf"), method="sigmoid", cv=3, ensemble=False)),
])

param_grid = {
    "clf__estimator__C":            [0.1, 1, 10, 100],      # 오분류 허용 정도(작을수록 부드러운 경계)
    "clf__estimator__gamma":        ["scale", 0.01, 0.1, 1],  # 한 샘플의 영향 반경(클수록 국소적=과적합 위험)
    "clf__estimator__class_weight": [None, "balanced"],     # 클래스별 수집량이 어긋났을 때 대비
}
```

- **StandardScaler를 붙인 이유**: RBF 커널은 거리 기반이라 차원별 스케일이 다르면 특정 좌표축이
  거리 계산을 지배한다. 정규화를 이미 했더라도 z축(깊이)은 MediaPipe 추정값이라 분산이 다르게 나올
  수 있어 표준화를 한 번 더 건다.
- **탐색 점수는 Macro F1(신호 7종)**: 05_모델카드_v3 §7-1에서 "Macro F1은 negative를 빼고 계산"으로
  확정했으므로, 하이퍼파라미터를 고르는 기준도 같은 지표로 맞췄다. 최적화 지표와 보고 지표가 다르면
  엉뚱한 모델이 뽑힌다.

### 4-2. 확률 보정과 τ 결정

`is_reject`(미판정)를 가르려면 "이 예측을 얼마나 믿을 수 있는가"라는 확률이 필요하다. SVM은 원래
확률을 내지 않으므로 **Platt scaling**(내부 교차검증으로 시그모이드를 적합)을 씌운다. 학습이 조금
느려지지만, τ 없이는 미판정률 KPI(≤5%) 자체를 만들 수 없다.

> 구현 메모: 흔히 쓰는 `SVC(probability=True)`는 **scikit-learn 1.9에서 deprecated(1.11 제거 예정)** 라
> 권장 API인 `CalibratedClassifierCV(SVC(), ensemble=False)`를 쓴다. 동작(시그모이드 보정)은 같다.
> 보정의 내부 `cv=3`은 인물 단위가 아니지만, 이는 보정 곡선에만 영향을 주고 결정 경계는 건드리지
> 않는다. **τ를 고르는 확률은 아래 절차에서 GroupKFold로 따로 뽑으므로** 인물 단위 원칙은 지켜진다.

τ는 05_모델카드_v3 §8-1 절차를 그대로 코드로 옮겼다.

1. train/val에서 **교차검증 확률**(`cross_val_predict`, GroupKFold)을 모은다 — test는 최종 보고용으로 남긴다
2. τ를 0.50 ~ 0.95까지 0.05 간격으로 훑으며 정답률 / 오분류율 / 미판정률을 재계산
3. **치명 오분류("정지"→다른 클래스)가 1건이라도 있는 τ는 먼저 탈락** (KPI 0건이 최우선 제약)
4. 정답률 ≥ 92%, 오분류율 ≤ 3%, 미판정률 ≤ 5%를 **동시에** 만족하는 후보만 남김
5. 그중 **미판정률이 가장 낮은 값**을 채택 — 학습자가 불필요하게 재시도하는 횟수를 줄이기 위함

모두 만족하는 τ가 없으면 노트북이 경고를 띄우고 차선책을 고른다. 그때는 **모델을 더 만지기 전에
데이터 추가 수집이나 클래스 재설계를 검토**하고, 그 사실을 06_테스트·평가리포트_v3 §1-3 / 08_리스크레지스터에
남기는 것이 맞다.

> 학습 전 기본값은 τ=0.75, N=3프레임이다(05_모델카드_v3 §8-0). 실측 데이터가 없는 상태에서 고른
> 잠정치이고, 위 절차로 확정한 값이 번들에 실려 서비스가 자동으로 그 값을 쓴다.

## 5. match_score는 분류와 따로 계산한다

`predicted_class`(무엇으로 판정했는가)와 `match_score`(얼마나 비슷한가)는 **다른 질문**이다.
학습자 입장에서 "정답이지만 70점", "정답이고 95점" 같은 피드백이 나와야 교육 도구로 쓸모가 있다.

- 클래스별 **centroid**(같은 클래스 학습 벡터의 평균)를 템플릿으로 삼는다.
- 추론 시 현재 63차원 벡터와 예측 클래스 템플릿의 **코사인 유사도**를 잰다.
- 0~100 매핑은 05_모델카드_v3 §2가 "percentile 매핑"을 요구한다. 분포를 알아야 하므로, 노트북이
  검증셋에서 **같은 클래스 유사도의 5·95 퍼센타일**을 구해 번들에 싣고, 서비스는 그 구간을 0~100으로
  선형 매핑한다([`src/cognition/templates.py`](src/cognition/templates.py)).

템플릿은 `sign_templates.json`으로도 내보낸다. 이 파일을 데이터 담당에게 넘기면
`services/data/src/seed_templates.py`가 DB(`sign_templates` 테이블)에 넣고, 그제서야 서비스의
match_score가 0이 아닌 값을 낸다. **DB가 비어 있으면 match_score는 0으로 안전하게 동작**한다.

## 6. 산출물과 로컬 적용

### 6-0. 학습 실행 (로컬)

```bash
cd services/vision
pip install -r requirements.txt        # scikit-learn, joblib 필요
python training/train_svm.py           # 기본: 세션 단위 5겹, 63차원
```

처음 실행은 JSON 27,735건을 읽느라 100초쯤 걸리고, 그 뒤로는 특징벡터 캐시
(`training/.feature_cache.npz`)를 써서 **0.7초**에 끝난다. 데이터가 추가·변경되면 캐시가 자동으로
무효화된다(클래스별 파일 수와 최신 mtime을 지문으로 쓴다).

| 자주 쓰는 옵션 | 용도 |
| --- | --- |
| `--dry-run` | 학습 없이 데이터 분포·세션 수만 확인 |
| `--per-class 300` | 클래스당 상한. 빠르게 한 바퀴 돌려볼 때 |
| `--with-orientation` | 손 방향 6차원 추가 (§2-1). **자체 촬영 데이터 확보 후에** |
| `--split subject` | 자체 촬영 데이터가 들어온 뒤 인물 단위로 (§3) |
| `--grid` | 하이퍼파라미터 탐색. 수십 분 걸리니 최종 학습 때만 |
| `--no-cache` | 캐시를 무시하고 JSON에서 다시 읽기 |

만드는 것:

| 파일 | 어디로 | 용도 |
| --- | --- | --- |
| `svm_classifier.joblib` | `services/vision/models/` (자동) | 모델 + classes + τ + match_score 보정 + `feature_mode` 포함 번들 |
| `sign_templates.json` | 데이터 담당 → `seed_templates.py` | 클래스별 centroid (match_score용 DB 시드) |

번들에 τ와 보정값까지 함께 담는 이유는, **모델과 임계값이 따로 놀지 않게** 하기 위해서다. 모델을
새로 학습하면 확률 분포도 바뀌므로 τ도 같이 바뀌어야 한다. 파일 하나만 교체하면 둘 다 갱신된다.

```bash
# ① 서비스가 모델을 물었는지 확인
docker compose up --build vision
curl http://localhost:8001/health     # model.loaded == true, tau, classes 확인

# ② 실제로 잘 맞히는지 눈으로 확인 (노트북 웹캠)
cd services/vision
pip install -r requirements-dev.txt
python scripts/webcam_check.py        # 손을 비추면 예측 클래스·confidence·match_score가 뜬다
```

②는 **숫자(정답률)만으로는 안 보이는 문제**를 잡는 단계다. 예를 들어 좌회전/우회전이 실제로는 잘
갈리는지, 손을 천천히 바꿀 때 N프레임 안정화가 답답하지 않은지, 특정 각도에서만 무너지는지 같은 것들.
webcam_check는 운영과 **같은 `cognition/` 코드**를 쓰므로, 여기서 본 판정이 곧 RPi5에서의 판정이다
(카메라 기종 차이는 남는다 — 최종 확인은 Pi Camera Module 3로).

환경변수 `CONFIDENCE_THRESHOLD`를 주면 번들의 τ를 **덮어쓴다**(운영 중 급히 조일 때용).
평소에는 설정하지 않고 번들 값을 쓰는 것을 권장한다.

## 8. 지금 상태 (2026-09-21 기준)

### 8-0. 확인된 라이브러리 버전

실제로 설치해 검증한 현재 버전대: **mediapipe 1.0.1 / scikit-learn 1.9.1 / numpy 2.5.x / opencv 5.0**.

- mediapipe 1.x에서도 Tasks API(`HandLandmarker`, `RunningMode.LIVE_STREAM`, `mp.Image`)는 그대로라
  코드 수정이 필요 없었다. 다만 **레거시 `mediapipe.solutions` 모듈은 제거**되어, 모델카드에 있던
  "느리면 `solutions.hands`로 교체" 폴백은 폐기하고 다른 대안으로 바꿨다 (05_모델카드_v3 §3-1).
- **scikit-learn 버전은 학습 환경과 이 서비스가 맞아야 한다** — 어긋나면 joblib 로드가 깨지거나
  조용히 다르게 동작한다. 번들 metadata의 `sklearn_version`과 실제 설치 버전을 `model_store`가
  비교해 경고를 띄우도록 해뒀다. 경고가 보이면 재학습하거나 서비스 쪽 버전을 맞출 것.
  로컬 학습이 기본이 되면서 이 위험은 크게 줄었다(같은 머신에서 학습하고 추론하므로).


- ✅ **학습 데이터 확보됨 (2026-09-20)** — 데이터 담당(김지훈)이 공개 데이터셋 3종에서 수신호 7종
  **27,735건**을 변환해 넣었다(`services/data/build_dataset.py`). 전량이 `normalize.py`를 통과한다.
- ✅ **모델 완성 (2026-09-22)** — `python training/train_svm.py` 한 줄. 산출물
  `models/svm_classifier.joblib`(0.3MB) + `sign_templates.json`.
- 📊 **공개 데이터 세션 단위 실측**: 정답률 **88.68%** / Macro F1 **0.879** / 치명 오분류 **4건**.
  관절 특징(§2-2) 도입으로 77.57% → 88.68%, 최대 혼동 쌍(주의↔우회전)은 2,530건 → 781건.

- ✅ **negative 방침 확정 (2026-09-21 안건 2 A)** — 7클래스만 학습하고 τ 미달을 미판정으로 처리.
