손을 찾아 21개 점으로 바꾼다

MediaPipe HandLandmarker가 화면에서 손을 찾아 관절 21개의 3차원 좌표를 돌려준다. 여기서부터는 사진이 아니라 숫자 63개(21점 × x,y,z)만 다룬다.

픽셀을 버리고 좌표만 쓰는 이유: 조명·배경·옷 색이 바뀌어도 관절 위치는 그대로다. 딥러닝으로 사진을 통째로 학습하는 것보다 훨씬 적은 데이터로 된다.

실시간 모드를 골랐다. MediaPipe에는 VIDEO와 LIVE_STREAM 모드가 있다. 코드는 VIDEO가 쉽지만, 우리는 로봇이 반응하는 제품이라 지연이 곧 품질이다. 비동기 콜백으로 프레임을 흘려보내는 LIVE_STREAM을 택했다.

둘 다 씁니다. 다만 딥러닝은 가져다 쓰고, 우리가 직접 학습시킨 건 고전 머신러닝입니다. 먼저 용어부터 정리하면:

용어 — 포함 관계

“AI 비전”은 기법 이름이 아니라 분야 이름입니다 — “카메라로 본 것을 이해한다”는 문제의 종류죠. 같은 비전 문제를 딥러닝으로 풀 수도, 고전 머신러닝으로 풀 수도, 아예 규칙만으로 풀 수도 있습니다.

깊이 보기 — 왜 CNN을 직접 학습시키지 않았나

후보는 두 갈래였습니다. A 랜드마크 좌표 + 가벼운 분류기, B 손 이미지를 잘라 CNN에 넣기(딥러닝). A를 골랐고, 이유는 넷입니다.

  • 데이터가 적다. CNN을 제대로 학습시키려면 클래스당 수천~수만 장이 필요합니다. 우리는 처음에 클래스당 300장을 목표로 했습니다. 저차원 벡터를 쓰는 고전 분류기에는 충분하지만 CNN에는 턱없이 부족합니다.
  • 조명·배경 문제를 MediaPipe가 이미 해결해준다. 픽셀을 직접 다루지 않으니 배경이 바뀌어도 관절 좌표는 비슷하게 나옵니다. 딥러닝이 잘하는 일을 이미 딥러닝이 해준 셈입니다.
  • “얼마나 비슷한가”를 공짜로 얻는다. 같은 좌표 공간에서 각도만 재면 일치율이 나옵니다. CNN이었다면 그 지표를 위한 설계를 따로 해야 합니다.
  • 팀원이 설명할 수 있어야 한다. 4명 중 2명이 비전공자이고 각자 자기 파트를 발표해야 합니다. 조절 손잡이가 2개인 모델이, “어느 층을 얼마나 얼렸는지” 설명해야 하는 CNN보다 유리합니다.

이런 구조 — 사전학습된 큰 모델을 고정된 특징 추출기로 쓰고 그 위에 가벼운 분류기를 얹는 것 — 은 데이터가 적을 때 흔히 쓰는 표준적인 선택입니다.

같은 “정지”라도 손이 화면 왼쪽에 있는지 오른쪽에 있는지, 가까운지 먼지, 기울었는지에 따라 좌표 63개는 전부 달라진다. 그대로 학습하면 모델이 손모양이 아니라 “손이 어디 있었는지”를 외운다.

여기서 실제 판정이 일어난다. 특징 23개를 받아 일곱 이름 중 하나를 고르는 단계다.

SVM 서포트 벡터 머신 · RBF 커널 sklearn.svm.SVC(kernel="rbf", C=10, gamma="scale", class_weight="balanced")
이 알고리즘의 네 가지 성질
성질 1
가장 넓은 길을 낸다

두 무리를 가르는 선은 무수히 많다. SVM은 그중 양쪽에서 가장 멀리 떨어진 선을 고른다. 그 여백을 마진이라 한다. 학습 데이터에 딱 붙지 않고 여유를 두므로, 처음 보는 손에 더 강하다.

성질 2
경계 근처만 기억한다

경계를 정하는 데 쓰이는 건 경계 가까이 있는 소수의 점뿐이다. 멀리 있는 점은 영향이 없다. 그 소수를 서포트 벡터라 하고, 이름도 여기서 왔다. 27,735건을 학습해도 모델이 0.3MB인 이유다.

성질 3
휜 경계를 만들 수 있다

손모양 사이 경계는 직선이 아니다. RBF 커널은 각 점 주위에 종 모양 영향력을 두고 그걸 합산해 곡선 경계를 만든다. 직선으로 못 가르는 것을 가른다.

성질 4
조절 손잡이가 둘뿐이다

C(틀린 걸 얼마나 봐줄까)와 γ(한 점의 영향이 얼마나 멀리 갈까). 이 둘만 정하면 된다. 재현이 쉽고 발표에서 설명이 된다 — 5주 일정에서 중요했다.

RBF 커널 — 직선으로 못 가를 때

현실의 경계는 직선이 아닌 경우가 많습니다. 커널은 “거리로 유사도를 재는 자”를 바꿔 끼워 휘어진 경계를 만들게 해줍니다. 우리가 쓴 RBF는 가장 흔한 것으로, 각 점 주위에 종 모양 영향력을 두고 그걸 다 더해서 경계를 만듭니다.

// RBF SVM이 판정할 때 실제로 계산하는 식 f(x) = Σ αᵢ · yᵢ · K(xᵢ, x) + b ↑ 서포트 벡터 하나하나의 영향력을 합산 K(a, b) = exp( −γ · |a − b|² ) ↑ 두 점이 가까울수록 1에 가깝고, 멀수록 0에 가까움

7개 클래스는 어떻게 가르나

SVM은 원래 둘을 가르는 도구입니다. 7개를 가르려고 모든 두 클래스 쌍마다 하나씩 만들어 투표시킵니다 — 7개면 21개 조합이니 이진 분류기 21개가 투표해서 최다 득표를 답으로 냅니다.

확신도(확률)는 원래 안 나온다

SVM이 내놓는 건 “경계에서 얼마나 떨어졌나”지 확률이 아닙니다. 그런데 우리는 τ로 “확신이 부족하면 미판정” 처리를 해야 하니 확률이 필요합니다.

그래서 Platt scaling을 씁니다 — 경계까지의 거리를 0~1 확률로 바꿔주는 작은 함수를 따로 학습시키는 방법입니다. 이때도 주의할 게 있는데, 같은 데이터로 SVM과 이 변환기를 둘 다 학습시키면 확률이 낙관적으로 부풀려집니다. 그래서 교차검증으로 분리해 학습시킵니다.

깊이 보기 — ‘기준 손(중심)’은 어떻게 만드나

어렵지 않습니다. 그 클래스 학습 샘플들의 평균입니다.

// 클래스 "정지"의 중심 = 정지 샘플 308개의 평균 중심[k] = ( 샘플1[k] + 샘플2[k] + ... + 샘플308[k] ) / 308 ↑ 23개 숫자 각각을 따로 평균낸다 // 결과: 23개 숫자로 된 "평균적인 정지 손"

이 페이지의 손 그림도 같은 방식으로 만들었습니다 — 학습 데이터에서 손가락별로 “펴진 상태의 평균 위치”와 “접힌 상태의 평균 위치”를 구해 두고, 켜고 끌 때마다 조립합니다. 그래서 7종을 합성해 넣으면 7/7 모두 자기 클래스가 1위로 나옵니다.

중심은 두 곳에 쓰입니다 — 화면에 보여주는 일치율, 그리고 다음 단계의 소속 게이트. 같은 값을 재활용합니다.

왜 거리로 재는가 — 점수 함수 비교 공개 데이터

분류기가 내는 확률은 7종 안에서 합이 1이 되도록 정규화된다. 그래서 엄지만 편 손처럼 학습한 적 없는 입력이 와도 “그나마 가장 비슷한” 클래스가 높은 값을 받는다. 실제로 재보니 모르는 손모양의 83%가 확신도 검사를 그냥 통과했고, 그중 77%는 확신도 0.90 이상이었다.

확신도는 “얼마나 확신하나”를 잴 뿐 “애초에 7종에 속하나”를 재지 못한다. 그래서 중심까지의 거리를 따로 본다. 분리 능력을 재보면 차이가 분명하다.

코사인 유사도 — 두 벡터가 이루는 각도

23개 숫자 두 묶음이 얼마나 닮았는지를 재는 방법은 여럿입니다. 우리는 방향이 얼마나 같은가를 재는 코사인 유사도를 씁니다.

cos(a, b) = (a · b) / ( |a| × |b| ) // a · b = a₁b₁ + a₂b₂ + ... + a₂₃b₂₃ (내적: 짝끼리 곱해서 전부 더함) // |a| = √(a₁² + a₂² + ... + a₂₃²) (길이) // 결과: 1이면 완전히 같은 방향, 0이면 직각, -1이면 정반대

왜 그냥 거리가 아니라 각도인가

두 벡터의 길이 차이를 무시하기 때문입니다. 손이 조금 크거나 손가락이 조금 길어서 숫자가 전체적으로 커져도, 비율이 같으면 같은 손모양으로 봐야 합니다. 코사인은 그 비율만 봅니다.

학습 데이터의 분포에서 뽑는다

클래스 하나를 정해서, 그 클래스 학습 샘플 전부가 자기 중심과 얼마나 닮았는지를 재면 분포가 하나 나옵니다. 대부분 0.99 근처에 몰려 있고, 자세가 어정쩡했던 소수가 아래쪽에 깔립니다.

// 클래스 c 의 기준값 기준[c] = percentile( { cos(샘플, 중심[c]) : c 의 모든 학습 샘플 }, 10 ) // 판정할 때 예측 = SVM(x) if cos(x, 중심[예측]) < 기준[예측]: → 미판정 (reason = "out_of_distribution")

왜 클래스마다 값이 다른가

전역 기준값 하나로는 쓸 수 없기 때문입니다. 클래스마다 “보통 얼마나 닮는지”의 범위가 다릅니다. 실제로 이런 역전이 일어납니다:

③ N프레임흔들리지 않는가연속 3프레임손을 바꾸는 중의 순간적 오판

셋 중 하나라도 걸리면 미판정으로 내보낸다. 교육 제품에서는 “모르겠다”가 “틀린 답을 자신 있게 주는 것”보다 낫다 — 틀린 시범을 따라 하게 만드는 게 가장 나쁘기 때문이다.

당연히 나오는 질문 — 안 본 데이터가 왜 더 높은가

학습에 쓴 공개 데이터에서는 88.7%인데, 학습에 쓰지 않은 자체 촬영에서는 97.1%가 나왔다. 보통은 반대여야 한다 — 안 본 데이터가 더 어려워야 정상이다. 그래서 세 가지를 확인했다.

① 자체 촬영분이 학습에 섞였나 — 아니다

학습 스크립트는 datasets/processed(공개 데이터)만 읽는다. 자체 촬영분은 self_recorded로 폴더가 분리돼 있다. 모델 파일에 기록된 학습 건수 27,735건이 공개 데이터 수와 정확히 일치한다 — 섞였다면 늘었을 것이다.

② 집계 단위가 유리했나 — 일부만

자체 촬영은 3프레임 다수결로 집계하므로 유리할 수 있다. 그래서 프레임 단위로도 재봤다 — 95.6%였다. 다수결 덕은 1.5%p뿐이고, 같은 기준으로 놓아도 여전히 +6.9%p 높다.

③ 데이터 난이도가 다르다 — 이게 진짜 이유

같은 클래스 안에서 샘플이 얼마나 뭉쳐 있는지 쟀다. 하위 5%(가장 어정쩡한 샘플)를 보면 차이가 확연하다.

어느 쪽을 믿어야 하나 — 둘 다, 용도가 다르다. 88.7%는 어떤 방법이 나은지 비교하는 데 쓴다(27,735건이라 비교가 안정적이다). 97.1%는 실제 쓸 때 얼마나 맞나를 재는 데 쓴다 — 우리 제품은 카메라 1대 고정에 학습자가 안내를 보고 수행하는 환경이라 이쪽이 실사용에 가깝다.

다만 97.1%를 과신하면 안 된다. 105시도뿐이고 촬영자 둘 다 수신호를 아는 팀원이다. 진짜 초보 학습자는 공개 데이터 쪽에 가까운 어정쩡한 자세를 낼 것이고 — 게이트와 τ를 둔 것이 정확히 그것 때문이다.
가장 위험했던 순간 — 98.81%가 허수였다 공개 데이터

정답률 — 27,735건 중 맞힌 비율. 같은 모델·같은 데이터이고 나누는 방식만 다릅니다.

첫 학습에서 98.81%가 나왔다. 너무 좋아서 파일명을 뒤졌더니 (2)가 붙은 복사본과 연속 촬영 컷이 섞여 있었다. 전체의 97.7%가 805개 세션에 묶여 있었고, 무작위로 나누면 사실상 같은 사진을 학습하고 그 사진으로 시험하는 셈이었다. 세션을 한쪽에만 두고 다시 재니 77.57% — 진짜 실력이었다.

또 한 번은 측정 도구가 문제였다. 특징을 바꾼 뒤 웹캠 로그로 재니 28.2%가 나와 모델을 되돌릴 뻔했다. 원인은 숫자키로 라벨을 찍고 수백 프레임을 계속 기록한 방식이었다 — 손을 만드는 중, 자세가 풀리는 순간이 전부 그 라벨로 들어갔다. (“정지”로 라벨링된 두 구간의 닮은 정도가 0.54였다.) 카운트다운 후 3프레임만 찍는 방식으로 같은 손을 다시 재니 100%였다. 이상한 숫자가 나오면 모델보다 측정을 먼저 의심한다.
