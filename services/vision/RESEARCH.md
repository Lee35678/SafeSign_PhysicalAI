# vision_research — 딥러닝으로 안전장치를 대체할 수 있는가

> 이 브랜치는 **연구용**이다. 운영 파이프라인은 `feature/vision`에 있다.
> 여기에는 SVM 코드가 없다 — 딥러닝만 다루고, 운영 모델의 **기록된 수치와 비교**한다.

## 0. 질문

운영 모델은 `SVM(7클래스) → 소속 게이트(거리) → τ(확신도) → N프레임` 구조다.
"7종 밖"을 분류기 **바깥**에서 판단하고, 그 수치를 사람이 맞춰야 했다. 실제로 그 수치를 고르는
과정에서 두 번 과적합했다(11 §8-6). 그래서 물었다 —

> **딥러닝이 "모르겠다"를 스스로 판단하게 하면 그 손잡이를 없앨 수 있는가.**

## 2. 시도 ① — negative 를 8번째 클래스로 학습 (폐기)

`training/synth_negative.py` · `training/train_dl.py` · `scripts/evaluate_dl.py`

실제 negative 데이터가 48프레임뿐이고 그마저 평가용이라, 실제 데이터에서 **합성**했다.

| | 무엇 | 만드는 법 |
| --- | --- | --- |
| N1 | 미사용 손모양 25가지 | 손가락 관절 각도를 이식 (32조합 중 7개만 쓴다) |
| N2 | 두 클래스 사이 중간 자세 | 다섯 손가락을 각도 공간에서 보간 |
| N3 | 한 손가락만 반쯤 | 한 손가락만 각도 공간에서 보간 |

**무시 구간**: 보간 계수 α ∈ [0.35, 0.65]만 negative로 쓰고 [0.2,0.35]·[0.65,0.8]은 학습에서
뺐다. 경계를 사람이 긋지 않고 모델이 정하게 두기 위해서다.

### 중간에 잡은 오류

좌표를 직접 선형 보간하면 두 자세의 중간점이 호가 아니라 **현**이라 마디가 짧아진다.
실측으로 합성 손의 **90%가 사람 손 마디 길이 범위를 벗어났다**(N2 9.4%만 정상).
→ **각도 공간에서 보간하고 마디 길이는 원본 것을 쓰도록** 고쳐 91%로 회복했다.

### 결과 — 기준선을 넘지 못함

합성 조합 9가지(N1/N2/N3 × 가중치 1·2·4·8)를 전부 학습시켰다. KPI는 모두 통과하지만
**애매 차단이 최대 75%로 기준선(81.2%)에 못 미쳤고**, 그 지점에서 정답률이 94.3%로 떨어졌다.

### 왜 안 되는가

합성물이 실제 실패가 일어나는 자리에 없다. GMM 로그우도 기준으로 —

```
  -103  N1 (미사용 손모양)     너무 쉬움. 거리 게이트가 이미 99% 막는다
   -40  실제 애매한 자세        ← 덮어야 하는 구간
    -6  N2·N3 (보간)          너무 정상에 가까움
   +12  실제 정상 자세
```

**합성물이 진짜를 양쪽에서 감싸기만 하고 덮지 못한다.**

더 근본적으로는 — 밀도 모델(게이트)은 *양성이 어디 있는지*를 배우고 나머지를 전부 거부하므로
**한 번도 본 적 없는 negative에도 통한다.** 반면 negative 클래스 학습은 *내가 준 negative*만 배운다.
실제로 게이트를 함께 붙였을 때 애매 차단이 게이트 단독과 **똑같았다** — 학습한 negative 클래스가
아무것도 더하지 못했다는 뜻이다.

> ⚠️ **나중에 찾은 결함 (2026-09-23).** 합성의 재료인 랜드마크 캐시(`build_landmark_cache.py`)가
> 세션 키로 **저장 파일 이름(public_00000 …)** 을 쓰고 있었다. 사실상 샘플마다 다른 값이라
> "합성 negative 는 출처 세션을 따라간다"는 누수 방지가 **작동하지 않았다.** 그래서 학습 로그의
> held-out 정확도(93.6%)는 부풀려진 값이다. 다만 위 결론은 **실제 촬영 데이터로만** 채점한 것이라
> 이 결함의 영향을 받지 않는다 — 누수는 합성 쪽을 유리하게 만들 뿐인데 그래도 졌다.
> 세션 키는 원래 `train_svm.py` 규칙으로 고쳤고(805개 세션, 특징 캐시와 정확히 일치), 이후 실험은
> 전부 고친 캐시로 했다.

## 3. 시도 ② — Evidential Deep Learning (현재)

`src/cognition/edl.py` · `training/train_edl.py` · `scripts/evaluate_edl.py`

negative 데이터를 **한 건도 쓰지 않는다.** 신경망이 확률 대신 **증거**를 내고, 거기서 나온
디리클레 분포의 **불확실성 질량**으로 거부한다.

```
e_k = softplus(logit_k) ≥ 0      클래스 k 의 증거
α_k = e_k + 1                     디리클레 파라미터
S   = Σα_k = Σe_k + K             증거 총량
p_k = α_k / S                     기대 확률   (이것만으로 합이 1)
b_k = e_k / S                     믿음 질량
u   = K / S                       불확실성 질량

          Σb_k + u = 1            ← 핵심 항등식
```

> **헷갈리기 쉬운 곳**: 항등식이 성립하는 것은 `p`가 아니라 **`b`** 다. `p`는 그 자체로 합이 1이라
> "모르겠다"를 담을 자리가 없다 — softmax와 같은 한계다. 그래서 거부 판단에는 `b`와 `u`를 쓴다.
> (구현 중 이 부분을 틀렸다가 `tests/test_edl.py`가 잡았다.)

손실은 Sensoy et al.(2018) Eq.5 (MSE 형태) + **증거 억제 KL 항**. KL 항은 정답 클래스의 증거를
지운 뒤 균등 디리클레로 끌어당긴다 — "틀린 클래스에는 증거를 내지 마라". 이게 EDL의 심장이고,
없으면 신경망이 모든 것에 자신만만해진다.

### 설계 중 실측으로 고친 두 가지

| 바꾼 것 | 정상 vs 애매 AUC | 이유 |
| --- | --- | --- |
| 치명 가중치 10 → 1 | 0.607 → 0.717 | 정지 가중치가 105까지 튀면서 학습이 왜곡됐다 |
| BatchNorm → LayerNorm | 0.717 → 0.791 | BatchNorm은 낯선 입력을 **배치 통계로 끌어당긴다** |
| KL 가중치 1 → 3 | (함께 반영) | 증거를 0으로 누르는 압력을 키운다 |

정규화 층 비교 (λ=3, 치명가중치 1): **layer 0.791** > none 0.722 > batch 0.717.

### 증거 활성 함수 비교 (2026-09-23)

logit 을 0 이상의 증거로 바꾸는 함수. 세션 분할 고정, 학습 시드 3개 평균±표준편차.

| 활성 | 식 | 공개 정답률 | 오답탐지 AUC | **정상vs애매 AUC** | u 중앙값 정상/애매 |
| --- | --- | --- | --- | --- | --- |
| relu | max(0, z) | 71.04±24.98% | 0.950 | 0.712±0.040 | 0.111 / 0.425 |
| softplus | log(1+eᶻ) | 90.66±0.28% | 0.921 | 0.769±0.017 | 0.100 / 0.225 |
| **exp** | e^clamp(z,±10) | **91.66±0.30%** | 0.918 | **0.845±0.010** | **0.001 / 0.474** |
| *운영 모델* | | *88.7%* | — | *0.820* | |

- **exp 가 처음으로 운영 게이트(0.820)를 넘었다.** 아는 입력은 증거가 지수적으로 커져 u 가 0 에
  붙고(중앙값 0.001), 모르는 입력은 증거가 빠르게 0 쪽으로 줄어 u 가 크게 남는다 — 대비가 벌어진다.
  logit 을 ±10 으로 잘라 폭주를 막았다.
- **relu 는 불안정하다.** 시드 2에서 증거가 죽어(음수 구간 기울기 0 → dead evidence) 정답률이
  35.7% 로 무너졌다. 평균이 71% 인 이유다.
- 임계값 없는 규칙(`u > max b`)에서 exp 의 애매 차단은 47.9% — AUC 는 이겼지만 **이 규칙의 동작점은
  아직 운영 모델(81.2%)에 못 미친다.** 거부 규칙의 기준을 어떻게 정할지는 따로 풀어야 한다(§5).

→ `train_edl.py` 기본값을 exp 로 바꿨다.

### 거부 규칙

| | 규칙 | 임계값 |
| --- | --- | --- |
| relative (기본) | `u > max_k b_k` — 정리하면 `max_k e_k < K` | **없음** |
| threshold | `u > τ_u` | 있음 (`EDL_TAU_U`) |

### 결과

공개 데이터 세션 분리 정답률 **91.04%** — 운영 모델의 88.7%보다 **높다.**
u가 *오답*을 가려내는 AUC는 **0.922**로 잘 작동한다.

그런데 *OOD 거부*는 다르다.

| 거부 규칙 | 정답률 | 오분류 | 미판정 | 치명 | 애매 차단 | 웹캠 차단 |
| --- | --- | --- | --- | --- | --- | --- |
| **운영 모델 (기준선)** | 97.1% | 0.0% | 2.9% | 0 | **81.2%** | **40.5%** |
| `u > max b` (임계값 없음) | 95.2% | 0.0% | 4.8% | 0 | 18.8% | 20.8% |
| `u > 0.2` | 86.7% | 0.0% | 13.3% | 0 | 56.2% | 33.5% |
| `u > 0.3` | 93.3% | 0.0% | 6.7% | 0 | 43.8% | 29.3% |
| `u > 0.4` | 94.3% | 0.0% | 5.7% | 0 | 25.0% | 24.0% |
| KPI 목표 | ≥92% | ≤3% | ≤5% | 0 | — | — |

**정상 vs 애매 분리 AUC 0.791 — 코사인 게이트 0.820에 아직 못 미친다.**
KPI를 만족하는 어떤 동작점에서도 기준선만큼 막지 못한다.

## 3-1. 평가 설계를 다시 세웠다 (2026-09-23)

### 무엇이 잘못돼 있었나

| 문제 | 영향 |
| --- | --- |
| **val 셋이 없었다.** 자체 촬영 하나로 설계(정규화·λ·치명가중치·활성 함수)를 고르고 같은 데이터로 채점했다 | 위 표의 AUC(특히 exp 0.845)는 약간 낙관적이다 |
| **공개 데이터 분할이 치우쳐 있었다.** 세션 크기가 중앙값 1건·최대 2,700건으로 극단적이라, 무작위 세션 분할에서 train 에 좌회전 유도가 208건뿐이고 val 의 97%가 두 클래스였다 | "공개 정답률"은 치우친 클래스 구성 위에서 잰 값이다. 학습 데이터 구성도 치우쳤다 |
| **epoch 수를 검증하지 않았다.** 120·150 고정, 마지막 가중치를 그대로 씀 | 로그상 25~50 epoch 에 이미 평평했다 |
| 랜드마크 캐시의 세션 키가 파일 이름이었다 (§2 참고) | 합성 negative 실험의 누수 방지가 작동하지 않았다 |

### 고친 방법 — 개발은 공개 데이터 안에서만

자체 촬영(JH·me01)과 웹캠 로그는 **마지막 KPI 측정용**이다. 가중치 학습은 물론이고 epoch·설계를
고르는 데 써도 "처음 보는 데이터"가 아니게 된다. 그래서 개발 전체를 공개 데이터 안에서 끝낸다.

| 역할 | 공개 데이터 (클래스별·세션 단위) | 자체 촬영 · 웹캠 로그 |
| --- | --- | --- |
| **train** | 거대 세션 전부 + 작은 세션 일부 (26,557) | 손대지 않음 |
| **val** | 작은 세션들 (590, 클래스마다 46~134) — epoch·설계 선택 | 손대지 않음 |
| **test** | 작은 세션들 (588, val 과 같은 성격) — 개발 마지막에 한 번 | 손대지 않음 |
| **KPI** | — | **최종 모델이 정해진 뒤 한 번만** |

- **클래스별·세션 단위 분할** (`stratified_session_split`). 클래스 건수의 5%를 넘는 거대 세션은
  쪼갤 수 없으니 전부 train. 나머지 작은 세션을 큰 것부터 목표(70/15/15) 대비 가장 모자란 분할에
  넣는다. 그래서 **val 과 test 가 둘 다 "작은 세션 여럿"이라 성격이 같고**, 세션 겹침은 0이다.
- **"7종 밖"은 한 클래스 빼기(LOCO)로 잰다.** 공개 데이터에는 애매한 자세가 없으므로, 7종 중
  하나를 빼고 6종으로 학습한 뒤 뺀 클래스를 처음 보는 손모양으로 넣는다. 7번 반복해 평균한다.
  검증 = 아는 6종의 val vs 뺀 클래스의 train+val / 시험 = 아는 6종의 test vs 뺀 클래스의 test.
- **epoch 선택 규칙을 그래프를 보기 전에 정했다.** 5 epoch 마다 스냅샷 → 공개 val 정답률이
  최고치 1%p 이내인 epoch 중 LOCO 검증 OOD AUC(이동평균 3)가 가장 높은 것.
- **test 는 개발 마지막에 한 번만** 본다. epoch 곡선에도 test 는 그리지 않는다.

> ⚠️ **이 브랜치에서 자체 촬영은 이미 여러 번 봤다.** 합성 negative 비교, EDL 의 정규화·λ·치명
> 가중치, 증거 활성 함수를 자체 촬영 AUC 로 골랐다. 그래서 위 §2·§3 의 자체 촬영 수치는 검증 성격이
> 섞인 값이고, 이 브랜치 모델의 KPI 로 쓰면 안 된다. 깨끗한 KPI 를 원하면 **새 촬영자 1~2명의
> 데이터를 따로 모아** 최종 모델에만 한 번 쓰는 것이 정직하다.
> 운영 모델도 같은 문제가 있다 — 코사인 게이트 p10 을 자체 촬영으로 골랐다(보고서 §8-6).

## 4. 지금까지의 결론

| | 분류 | 거부 |
| --- | --- | --- |
| 딥러닝 | **91.0%** (SVM 88.7%) | AUC 0.791 |
| 운영 모델 | 88.7% | **AUC 0.820** |

**분류는 딥러닝이 이기고, 거부는 밀도 기반이 이긴다.** 세 가지 접근(프로토타입 거리, 합성
negative 8클래스, EDL)이 전부 같은 방향을 가리켰다 —

> 학습된 표현 위에서 "모른다"를 재는 것은, 양성 분포를 직접 모델링하는 것보다 어렵다.
> 신경망은 7종을 가르는 데 필요 없는 정보를 버리는데, 버려진 정보에 "7종 밖"이라는 단서가 있다.

다만 EDL은 **고칠 여지가 남아 있다.** 0.607 → 0.791까지 올린 것이 전부 구조 수정이었고,
아직 시도하지 않은 것이 있다.

## 5. 남은 시도 후보

1. **실제 negative 촬영** — 가장 확실하다. `record_dataset.py --ambiguous`로 200~300테이크.
   합성의 분포 불일치 문제가 통째로 사라진다.
2. **입력 공간 정규화 흐름** — 임베딩이 아니라 joint23 **입력 분포**를 직접 모델링.
   특징 붕괴를 피하면서 딥러닝을 쓰는 길.
3. **EDL + 밀도 앙상블** — u와 밀도 점수를 함께 쓴다. 연구 목적에는 어긋나지만 성능은 최선.
4. **다른 증거 활성 함수** — exp/ReLU 비교, 정규화 세기 재조정.

## 7. 학습 방법 — 공개 데이터만, early stopping

| 단계 | 무엇 | 선택 근거 |
| --- | --- | --- |
| 1 설정 | MLP 로 증거 활성 {softplus, exp, relu} × λmax {1, 3} × 정규화 {layer, batch} × 치명가중치 {1, 10} | 공개 val |
| 1+ 재확인 (Colab) | HandFormer-small 에서 활성·λmax | 공개 val |
| 2 구조 | MLP · MLP(증강 끔) · HandFormer small · base (· large, Colab) | 공개 val |
| 3 최종 | 고른 구조로 멤버 5개 | 공개 test 1회 |
| KPI | JH·me01 | **최종 모델에 한 번만** |

선택 규칙(결과를 보기 전에 정함): val 정답률 최고치 1%p 이내 후보 중 **한 클래스 빼기 OOD AUC 최대**.

**early stopping** — 감시 지표는 val EDL 손실(λ 는 λmax 로 고정해 계산). KL 가중치가 최대에 오른 뒤부터
판단하고, 0.1% 이상 개선이 15(Colab 20) epoch 동안 없으면 멈추고 **최고점 가중치로 되돌린다.** 정체
5 epoch 마다 학습률을 절반으로 낮춘다. 한 클래스 빼기 7회도 같은 규칙으로 멈춘다 — OOD 점수로 멈추게
하면 그 점수가 낙관적이 되기 때문이다. 연기 시험에서 MLP 는 50 epoch 에 멈췄고 최고점은 35 epoch 였다
(고정 150 epoch 였다면 100 epoch 를 낭비).

## 7-1. 결과 (2026-09-23, Colab T4 · 178분 · 공개 데이터만)

**선택 과정** (선택은 전부 공개 val, 규칙대로)

| 단계 | 결과 | 비고 |
| --- | --- | --- |
| 1 설정 (MLP 24조합) | softplus · λ1 · batch · 치명1 (LOCO 0.874) | 2·3등과 차이가 잡음 수준(±0.015). relu+λ3 은 정답률 93~95%로 탈락 |
| 1+ 재확인 (HF-small 4조합) | exp · λ1 (0.891) | softplus · λ1(0.888)과 사실상 동률 |
| 2 구조 | **HandFormer-base** (0.922) | MLP 0.874 → small 0.891 → **base 0.922** → large 0.908. 크기 효과가 base 에서 정점 |
| 3 최종 | base × 5 앙상블 | early stopping 최고점 epoch 평균 37 |

- λ 를 3으로 올리면 미지 차단과 정상 오거부가 **같이** 오른다 — 거르는 능력(AUC)이 아니라 기준선 위치만 바뀐다.
- 증강은 효과가 있다 (MLP 0.854 → 0.874).
- 모든 구성이 5~10 epoch 안에 수렴하고, early stopping 이 50~70 epoch 에서 멈췄다 (그래프: `reports/training_curves.png`).
- 뺀 클래스별로는 **우회전 유도 · 서행 · 주의** 가 어렵다 — 이웃 수신호와 손가락 하나 차이인 클래스들이다 (`reports/loco_curves.png`).

**같은 분할 · 같은 규칙에서 운영 방식과 비교** (공개 test, 자체 촬영 미사용)

| | SVM + 코사인 게이트 p10 (운영 방식) | HandFormer-base EDL |
| --- | --- | --- |
| test 정답률 | 97.28% | 96.94% |
| 한 클래스 빼기 AUC — val / test | **0.948 / 0.968** | 0.922 / 0.934 |
| test 정상 오거부 · 미지 차단 (각자의 동작점) | 12.6% · 95.7% | 4.1% · 59.3% |
| CPU 한 프레임 추론 (노트북 1스레드) | — | 12.3ms (멤버 5개) |

뺀 클래스별 test AUC — HandFormer 가 이긴 곳은 **좌회전 유도(0.983 vs 0.921)** 하나뿐이고, 서행(0.836 vs 0.958) ·
우회전 유도(0.872 vs 0.955) · 주의(0.921 vs 0.967)에서 크게 졌다.

> **결론.** 분류는 동률, **"처음 보는 손 거르기"는 운영 방식이 val·test 모두에서 앞선다.** 차이(0.03)는 설정 간
> 잡음(±0.015)보다 크다. 178분 학습한 딥러닝 모델이 입력 공간의 단순한 중심 거리를 이기지 못했다 — 앞선 세 가지
> 시도(프로토타입 거리 · 합성 negative · EDL MLP)와 같은 결론이다. 학습된 표현 위의 불확실성은, 7종을 가르는 데
> 필요 없는 정보를 버리면서 "7종 밖"의 단서도 함께 버린다.
>
> 동작점은 따로 봐야 한다. 운영 방식의 p10 은 공개 test 에서 **정상 자세 12.6%(val 20.0%)를 튕긴다** — 자체 촬영
> 에서 2.9%로 보였던 것과 차이가 크다. 공개 데이터의 '정상'이 ASL 사진이라 원래 들쭉날쭉하기 때문이지만, 실사용
> 초보 학습자가 어느 쪽에 가까운지는 아직 모른다.
