# SafeSign PhysicalAI 개발 로그 (Dev Log)

- 프로젝트: SafeSign PhysicalAI ("심기일전") — 산업 안전 수신호 교육용 피지컬 AI 제품
- 작성자: 송승호 (하드웨어·로봇동작 R, services/actuation·services/picar 담당)
- 최초 작성일: 2026-09-21
- 최근 갱신일: 2026-09-21

## 📌 프로젝트 개요

- **목적**: AI Hand(로봇손)가 수신호를 시범 → 학습자가 따라 함 → 카메라+MediaPipe+SVM으로 인식/판정 →
  AI Hand 재시범·picar 주행+LED·micro:bit LED 3개 물리 장치로 피드백을 주는 폐루프 안전교육 제품.
  화면 텍스트가 아니라 실제 로봇 동작으로 피드백을 준다는 점이 핵심 차별점.
- **기술 스택**: Python(FastAPI), TypeScript(MakeCode/micro:bit), MediaPipe HandLandmarker, SVM,
  BLE(`bleak`), Docker Compose. 4인 팀(vision/actuation/picar/web/data 서비스 분담).
- **관련 링크**: `document/10_PRD_v2.md`(종합 기획서), `shared/schemas/`(서비스 간 인터페이스 계약),
  `services/actuation/doc/`(하드웨어 스펙·핀맵·디버깅 이력)

## 📊 현재 상태 요약

- 전체 진척률: 설계 문서는 거의 확정 단계. mock 기준으로는 web↔vision↔actuation↔picar 파이프라인이
  end-to-end로 연결됐고, 실물 구동은 부품(카메라·picar·RPi4B) 도착 대기다. 웹 프론트엔드와 picar
  모터 구동은 아직 스캐폴딩 단계.
- 상태: 🟡 지연 (실물 부품 미도착, picar 모터 I2C 프로토콜 미확보) — actuation의 BLE 제스처 재현과

  크로스플랫폼이라 BLE 구간 검증은 동일하게 성립하고, 컨테이너/BlueZ 관련 항목만 RPi5로 미뤘다.
  - BLE 스캔: `BBC micro:bit [zezuz]`(`E5:4C:EF:73:24:A9`) 탐지 확인
  - `tests/ble_debug_services.py`로 UUID 실측 대조 — `6e400003`=write(RX), `6e400002`=indicate(TX)로
    `ble_bridge.py`의 상수와 일치함을 확인(표준 NUS와 반대인 것도 재확인)
  - `MOCK_HARDWARE=false`로 서비스 기동 → `/health`가 `microbit_connected: true` 반환
  - `/command` 7종(G1~G7) 전송 + AI Hand 손모양 육안 대조 완료 — 엄지 미동작으로
    `G3`↔`G6`, `G4`↔`G7`이 구별되지 않음을 확인(아래 "손모양 육안 대조 결과" 참고)
  - `/result` correct/incorrect → LED O/X 표시 정상 확인 (아래 부저 수정 후)
  - `/progress` → `P37`/`P17` 전송에 `OKP37`/`OKP17` 회신 확인(`status: ok`). LED 표시가 없는
    명령이라 회신값이 유일한 성공 근거인데, 왕복까지 정상으로 확인됨
- 검증 중 발견한 환경 이슈 2건(문서화 목적):
  - PowerShell에서는 bash식 `MOCK_HARDWARE=false uvicorn ...`이 안 된다 → `$env:MOCK_HARDWARE = "false"` 후 실행
  - PowerShell의 `curl`은 `Invoke-WebRequest` 별칭이라 `-d '{"..."}'`의 큰따옴표가 벗겨져 JSON이 깨진다
    → `curl.exe`를 쓰거나 `Invoke-RestMethod ... -Body (@{...} | ConvertTo-Json)` 사용.
    한글 `target_signal`은 파일(`cmd.json`, UTF-8)로 만들어 `--data-binary @cmd.json`으로 보낼 것

  RESULT 기능을 추가하면서 같은 호출을 다시 넣었던 것이다.

**결정 사항**
- **부저는 사용하지 않는다(확정).** `aihand_control.ts`에 `const BUZZER_ENABLED = false;`를 추가하고

  **LED 표시 시간 2초를 그대로 유지**한다(기존엔 부저 1초 블로킹 + 1초 대기로 2초였음).

**손모양 육안 대조 결과 (2026-09-21 실측)**

- 엄지 미동작 상태에서 **`G3`(좌회전_유도)↔`G6`(후진), `G4`(우회전_유도)↔`G7`(주의)이 실제로

  보고는 무엇을 따라 해야 할지 판단할 수 없다.
- 단, 교육 흐름 자체가 막히지는 않는다 — web 화면이 현재 목표 수신호 이름(`target_signal`)을
  이미 표시하므로(`GET /api/state`), 학습자는 **화면의 이름으로 구분하고 AI Hand는 보조 시범**으로
  기능한다. 인식·판정 경로(vision → 판정)는 로봇손과 무관하므로 KPI에는 영향이 없다.
- 제스처 재설계는 하지 않기로 이미 확정(위 결정 사항) — 시현 대응은 web 화면 안내에 의존한다.
  화면 문구/이미지 보강 필요 여부는 조은수(web 담당)와 협의 대상.
