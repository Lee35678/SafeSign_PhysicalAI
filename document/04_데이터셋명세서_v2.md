**손모양 변경 2건 사유** (2026-09-20 팀 승인, 상세는 02_설계문서_v2 §4 참고사항 5):
AiHand는 손가락을 펴짐/굽힘 2단계로만 제어한다. 우회전 유도의 "약지만 펴기"는 힘줄 구조상 **사람이
따라 하기 어렵고**(학습자가 못 따라 하면 교육 도구로 무의미), 확인/완료의 "따봉"은 **공개 데이터셋에
대응 클래스가 없어** 학습 데이터를 확보할 수 없었다.

> ⚠️ **negative의 의미가 좁아졌습니다.** "손 없음"은 `hand_detected=false`로 분류기 **이전 단계**에서
> 걸러지고 09_화면목록_v2 SC-04(카메라 인식 실패)로 처리된다. 따라서 분류기가 배워야 할 negative는
> **"손은 보이지만 7종 어디에도 해당하지 않는 자세"** 뿐이다. 공개 데이터셋의 `nothing` 폴더는 손이
> 없는 배경 사진이라 랜드마크가 0건 추출되어 쓸 수 없었다(§2 실측).

### 2-3. 🔴 확보 현황에서 드러난 문제 3가지

1. **negative 0건** — 위 ⚠️ 참고. 선택지: ① **7클래스로 운영**하고 애매한 자세는 τ 임계값(`is_reject`)으로
   미판정 처리(05_모델카드_v3 §8) ② "손은 있으나 7종이 아닌 자세"를 자체 촬영. **팀 결정 필요.**
2. **클래스 불균형 최대 18배** — 정지 308장 vs 좌회전_유도 5,629장. 데이터가 적은 클래스를 덜 맞히게
   되는데, 하필 **정지가 치명 오분류 KPI(0건) 대상**이라 3번과 직결된다.
   → 학습 시 `class_weight="balanced"` 적용 또는 `build_dataset.py --per-class`로 상한을 걸어 조정.
3. **치명 오분류 1건 발생** — 파이프라인 검증(2,708건, 5겹 교차검증)에서 정지 308장 중 1건이 다른
   클래스로 판정됨(0.3%). **01_프로젝트계획서_v4 KPI 목표는 0건이라 미달.**
   → 05_모델카드_v3 §8-1 절차 3의 "정지 클래스에만 더 높은 τ 적용"으로 완화 검토.

### 3-2. 자체 촬영 (평가용, 아직 미수행)

공개 데이터로는 **인물 단위 평가가 불가능**하므로(§4) 평가용 데이터는 반드시 직접 찍어야 한다.

| 항목 | 내용 |
| --- | --- |
| 촬영 대상 | 외부인 1~2명 (팀원 데이터와 겹치지 않게) |
| 촬영 규모 | 외부인 1~2명 × 8클래스 × 10회 = 80~160건 (05_모델카드_v3 §7-2) |
| 촬영 장비 | Raspberry Pi Camera Module 3 (CSI, RPi5 직결) — 02_설계문서_v2 §1-1 확정 사양과 동일 장비로 촬영해야 학습/실제 인식 조건이 일치함 |
| 촬영 환경 | 평범한 실내 조명 + 단순 배경 (악조건은 계획서 제외 범위) |
| 촬영 변인 | 카메라 거리 2~3단계, 손 기울임 ±15도 정도 |

> 공개 데이터는 촬영 환경·장비가 제각각이라 **실제 사용 환경(Pi Camera + 실내)과 분포가 다르다.**
> 자체 촬영 데이터는 평가뿐 아니라 "환경 차이로 성능이 떨어지는지" 확인하는 역할도 한다.

## 4. 데이터 분할 기준

> ⚠️ 원칙: 같은 사람의 손이 train/test에 섞이면 실제 정답률이 부풀려지므로 **인물 단위 분할
> (subject-wise split)을 강제 적용**한다.

**⚠️ 2026-09-20 정정 — 공개 데이터에는 이 원칙을 적용할 수 없다.** 공개 데이터셋에는 촬영자 정보가
없어 변환 시 `subject_id`가 전부 `"public"` 하나로 기록된다. 그룹이 1개뿐이라 인물 단위 교차검증
(GroupKFold)이 성립하지 않는다.

따라서 데이터 성격별로 역할을 나눈다:

| 데이터 | subject_id | 역할 | 인물 단위 분할 |
| --- | --- | --- | --- |
| 공개 데이터셋 27,735건 | `public` (단일) | **학습(train) + 하이퍼파라미터 탐색** | ❌ 불가 → 일반 교차검증으로 대체 |
| 자체 촬영 (팀원 4명) | 팀원별 ID | 학습 보강 + 검증 | ✅ |
| 자체 촬영 (외부인 1~2명) | 외부인별 ID | **최종 평가(test) — KPI 실측의 근거** | ✅ |

> 🔴 **공개 데이터로 낸 정답률(97.7%)은 KPI 달성 근거로 쓸 수 없다.** 같은 데이터셋 안에서 나눈
> 수치라 낙관적으로 부풀려져 있고, 실제 사용 환경(Pi Camera·실내·우리 팀원 손)과 분포도 다르다.
> **01_프로젝트계획서_v4의 KPI는 자체 촬영 데이터(외부인)로 측정한 값으로만 판단한다.**

   각자 Kaggle에서 내려받아 로컬에서 변환한다.
2. **출처·라이선스를 발표자료/결과보고서에 명시한다** — 특히 "ASL 지문자의 의미가 아니라 손모양만
   차용했다"는 점.
3. **학습 결과물(모델 가중치) 공개 범위는 팀 논의 후 결정한다.** ODbL/GPL의 copyleft가 파생물에
   어디까지 미치는지는 해석 여지가 있어, 공개 전 한 번 짚고 갈 것. (8_리스크레지스터 참고)
4. 자체 수집 데이터: 팀 내부 동의 하에 수집, 공개 범위 사전 협의.

## 6. 데이터 저장 형식 (확정, 2026-09-20)

```
services/data/datasets/
├── raw_public/{클래스명}/*.jpg                        # 공개 데이터 원본 — git 제외, 각자 내려받기
├── raw/{class_name}/{subject_id}_{index}.jpg          # 자체 촬영 원본 — git 제외
└── processed/{class_name}/{subject_id}_{index}.json   # 랜드마크 — git 제외
```

전처리 결과 JSON 1건 = 프레임 1장 (약 1.4KB):

```json
{
  "class_name": "정지",
  "subject_id": "public",
  "handedness": "Right",
  "landmarks": [{"id": 0, "x": -0.015630, "y": 0.093545, "z": 0.001524}, "... 21개"],
  "source": {"folder": "정지", "file": "hand5_0_bot_seg_1.jpeg"}
}
```

- **좌표는 `hand_world_landmarks`(실세계 미터 단위)** — 카메라 거리 변화에 강하다 (05_모델카드_v3 §3-4).
- **소수점 6자리로 반올림.** 손 전체가 약 0.1m라 6자리면 1마이크로미터 정밀도이고, 원본 정밀도를 다
  쓰면 파일 크기만 2배가 된다.
- `handedness`는 정규화 단계의 좌우 손 통일에 필요하다 (03_인터페이스계약서_v2 §3).
- `source`는 추적용 선택 필드 — vision의 학습 노트북은 무시한다.
- 이 형식은 `services/vision`의 학습 노트북과 `make_dummy_dataset.py`가 그대로 읽는다.
