## 1. 왜 “피지컬 AI”인가 (핵심 아키텍처 근거)

본 프로젝트는 카메라 인식만으로 끝나지 않고, 인식 결과가 **물리적 액추에이터로 되먹임되는 닫힌 제어 루프(closed-loop)** 구조를 갖는다. 이 점이 “웹캠 앱”과 본 시스템을 구분하는 핵심 근거이다.

```
[물리 입력]  학습자 손 (실제 3D 공간)
     ↓ 센싱
[Perception] 카메라 → MediaPipe Hand Landmarker → 21 keypoints
     ↓ 인지
[Cognition]  랜드마크 정규화 → 분류 + 일치율 산출 → 교육 상태머신
     ↓ 구동
[Actuation]  ① AI Hand : 정답 수신호를 물리적으로 시범 / 교정 자세 제시
             ② micro:bit : LED 매트릭스 정오답, 부저, 버튼 입력, 진행 표시
     ↓ 물리 출력
[물리 피드백] 학습자가 로봇 손을 보고 자기 손을 교정 → 다시 센싱
```

- 화면 텍스트가 아닌 **로봇 손의 물리적 시범**을 교보재로 사용. 산업 현장 수신호는 3차원 손 형상이므로 평면 디스플레이 교육은 손가락 겹침·각도 정보를 전달하지 못함.
- 인식 결과가 곧바로 물리 액추에이터로 되먹임되는 Human-in-the-loop 구조.

- **후보 B: 이미지 분류 기반** — 손 영역 crop → CNN 분류기 (사전학습 가중치 fine-tuning)

| 비교 항목 | 랜드마크 기반 | 이미지 분류 기반 |

## 3. AiHand 하드웨어 제약

- 손가락 서보 5개(굽히고 펴기) + 손목 서보 1개(좌우 회전, 180°)
- **손목을 상하로 꺾는 동작은 물리적으로 구현 불가** → 모든 수신호 후보는 ①손가락 모양 ②좌우 회전 조합으로만 표현
- 연속 제스처·동적 동작 추적은 하드웨어 제약상 제외 (계획서 제외 범위 참고)

## 4. 수신호 후보안 (분야별, 확정 전 초안)

> 출처: AiHand_수신호_분야별_설계안. **실제 표준 수신호(KOSHA 산업안전수신호 등)를 그대로 옮긴 것이 아니라 AiHand로 표현 가능하도록 재해석한 시안**이므로, 최종 확정 전 공식 자료와 대조 확인 필요.
> 

### 4-1. 산업 (제조/공장)

| 수신호 | 의미 | 로봇 표현 |
| --- | --- | --- |
| 정지 | 작업 중단 | 다섯 손가락 모두 펴기 + 정면 |
| 진행/작동 | 작업 시작 | 검지만 펴기 + 정면 |
| 좌측 이동 | 왼쪽 이동 지시 | 검지만 펴기 + 좌회전 |
| 우측 이동 | 오른쪽 이동 지시 | 검지만 펴기 + 우회전 |
| 위험/긴급정지 | 즉시 중단 | 주먹 쥐기 + 정면 |

### 4-2. 건설 (크레인/중장비 유도)

| 수신호 | 의미 | 로봇 표현 |
| --- | --- | --- |
| 정지 | 크레인 정지 | 다섯 손가락 펴기 + 정면 |
| 서행 | 천천히 진행 | 검지+중지 펴기 + 정면 |
| 좌회전 유도 | 장비 좌회전 | 검지만 펴기 + 좌회전 |
| 우회전 유도 | 장비 우회전 | 검지만 펴기 + 우회전 |
| 확인/완료 | 작업 완료 확인 | 엄지만 펴기 + 정면 |

### 4-3. 농업 (농기계 유도)

| 수신호 | 의미 | 로봇 표현 |
| --- | --- | --- |
| 정지 | 농기계 정지 | 다섯 손가락 펴기 + 정면 |
| 전진 | 앞으로 진행 | 검지만 펴기 + 정면 |
| 좌측 방향 | 좌측 이동 | 검지만 펴기 + 좌회전 |
| 우측 방향 | 우측 이동 | 검지만 펴기 + 우회전 |
| 대기 | 잠시 정지, 신호 대기 | 주먹 쥐기 + 정면 |

### 4-4. 수중 (다이빙/수중작업)

| 수신호 | 의미 | 로봇 표현 |
| --- | --- | --- |
| OK(이상없음) | 상태 양호 | 엄지+검지 원 모양 근사 표현 + 정면 |
| 정지 | 동작 중단 | 다섯 손가락 펴기 + 정면 |
| 주의/위험 | 위험 신호 | 주먹 쥐기 + 정면 |
| 왼쪽으로 | 좌측 이동 신호 | 검지만 펴기 + 좌회전 |
| 오른쪽으로 | 우측 이동 신호 | 검지만 펴기 + 우회전 |

**참고 사항**

1. “정지=다섯손가락+정면”, “좌/우회전=검지+좌/우회전” 패턴이 여러 분야에서 반복됨 → 공통 함수로 재사용하면 구현이 간결해짐.
2. 수중 OK 사인(엄지·검지 원 모양)은 AiHand 서보 각도로 완벽히 재현하기 어려울 수 있음 — 실물 테스트로 가장 유사한 각도값 탐색 필요.
> **어떻게 탐색하나요?** AiHand를 직접 움직여보며 서보 각도를 5~10도 단위로 바꿔가며 사진을 찍고, 팀원 투표로 “가장 OK 사인처럼 보이는” 각도를 고릅니다. 확정된 각도값은 03_인터페이스계약서_v1의 `servo_angles` 예시 값으로 옮겨 적으세요.
3. 현재 분야당 5개, 총 20개로 설계됨. 5주 일정상 부담스러우면 분야당 3~4개로 축소 가능.
4. 분야(카테고리) 선택은 micro:bit 버튼(A/B/A+B) 조합만으로 4개 분야 모두 매칭 불가 → 버튼 순환 방식(누를 때마다 산업→건설→농업→수중 순환) 또는 로고 터치 센서(V2) 활용 권장.

## 5. micro:bit 역할 정의

| 기능 | micro:bit 활용 | 비고 |
| --- | --- | --- |
| web 인터페이스 이동 | A/B 버튼 | 학습자가 마우스 없이 조작 |
| 정·오답 피드백 | 5×5 LED 매트릭스 (O/X/화살표) | 시각 피드백 |
| PC/RPi 연동 | USB 시리얼 (권장) 또는 라디오(2대 사용 시) | 시리얼 권장 |

> micro:bit ↔︎ 라즈베리파이는 **USB 시리얼**로 연결. BLE는 페어링 이슈로 시연 당일 사고 확률이 높음. 통신 프로토콜 상세는 03_인터페이스계약서_v1 참고.
>
