> **이 문서 작성법**
화면 목록은 “웹페이지에 실제로 몇 개의 화면(또는 화면 상태)이 필요한가”를 정하는 첫 산출물입니다. 아래 순서로 작성하세요.
> 
> 1. **시나리오 문서의 “단계”를 하나씩 따라가며, 화면이 바뀌는 지점마다 새 화면으로 분리합니다.** (예: 시나리오의 1~9단계를 그대로 화면 후보로 나열)
> 2. **같은 레이아웃에서 상태만 바뀌는 경우는 별도 화면이 아니라 “화면 내 상태”로 묶습니다.** 예를 들어 시나리오 5번(정답)·6번(오답)은 둘 다 “수신호 시범/인식 화면” 위에 뜨는 오버레이일 뿐, 화면 자체가 바뀌는 게 아닙니다 → 아래 표에서도 하나의 화면(SC-03) 안에 정답/오답 상태로 정리했습니다.
> 3. **예외 시나리오(카메라 인식 실패, 중간 이탈 등)도 화면 후보에 반드시 포함합니다.** 예외 화면을 빼먹으면 나중에 개발 중간에 “이 상황엔 뭘 보여주지?”로 막히게 됩니다.
> 4. **각 화면마다 “다음 화면(전환 경로)”을 반드시 적습니다.** 이게 채워지면 자동으로 사용자 흐름도(User Flow)의 초안이 됩니다 — 다음 산출물로 바로 이어집니다.
> 5. **필수/부가를 구분합니다.** 계획서의 “포함 범위(필수)”와 “부가 기능(여유 시)” 구분을 그대로 따르세요. 부가 기능 화면은 먼저 자리만 잡아두고, 필수 화면부터 와이어프레임으로 넘어가면 됩니다.
> 6. 표를 다 채운 뒤 **팀 회의에서 “화면 개수가 5주 안에 만들 수 있는 수준인지”를 한 번 검토**하세요. 화면이 너무 많으면 2번 원칙(상태로 묶기)을 다시 적용해 줄이는 것을 권장합니다.

### SC-03 진행 흐름 (2026-09-27 확정)

```
수신호 시작 ─▶ [시범 단계] AI Hand 시범 + 예시 사진 + 확인 버튼      ← 판정·SC-04 카운트 멈춤
                  │ 확인 버튼 / 스페이스바 → vision /reset
                  ▼
              [판정 단계]
       ┌──────────┼──────────────────────┐
    정답(즉시)   같은 오답 1초 유지       손 미검출 15회
       │          │                       │
   SC-03a     SC-03b → AI Hand 재시범     SC-04 ─(손이 보이면)─▶ 판정 단계
       │          → [시범 단계]로
   다음 수신호 [시범 단계] (마지막이면 SC-05)
```

- **왜 버튼인가**: 처음엔 “시범 후 3초 동안 판정 무시”였으나, 보는 데 걸리는 시간은 학습자마다 달라 고정값으로
  정하기 어렵다. 학습자가 직접 판정을 시작하게 했다.
- **왜 오답 1초 유지인가**: 버튼을 누른 뒤 손을 올리는 동작의 과도 자세는 버튼으로 막을 수 없다. web 없는 데모
  스크립트(`aihand_vision_picar_demo.py`)에서 같은 규칙으로 2026-09-25 7/7 통과했다.
- **예시 사진의 추가 효과**: AI Hand는 엄지 서보 고장으로 `좌회전_유도`↔`후진`, `우회전_유도`↔`주의`가 구별되지
  않는다(11_하드웨어설계서 §4.7). 사람 손 사진이 이를 보완한다.

- **SC-04 진입 임계값**: 15회 연속(약 3초) 잠정치. 시범 단계 카운트 정지를 반영한 뒤 실측 조정
- **SC-03 카메라 실시간 미리보기**: vision에 프레임 스트리밍 엔드포인트가 없어 자리표시자만 있다. 스트리밍
  방식(MJPEG/WebSocket 등)을 vision 담당과 협의 필요
- **SC-06 수료증 디자인**: 현재 canvas 기본 레이아웃. 정식 템플릿 확정 필요
- **SC-03에서 picar 동작을 어떻게 노출할지**: 화면에 picar 상태를 텍스트/아이콘으로만 표시할지, picar 실물 영상을 별도 카메라로 비출지 (시연 환경에 따라 결정)
- ~~**SC-07 이어서 하기 여부**~~ → **결정 (2026-09-18): 구현하지 않음.** 지금은 웹 화면의 세부 기능보다
  인식→판정→Actuation 입력-출력 파이프라인이 제대로 동작하는지 확인하는 것이 우선이라, 세션 저장/복원
  로직(구현 비용 대비 낮은 우선순위)은 만들지 않기로 했습니다. 재접속 시 이전 세션과 무관하게 항상
  "처음부터"만 지원합니다. 파이프라인 검증이 끝나고 웹 화면을 다듬는 단계에서 필요하면 재검토하세요.
- **(제거됨) 구 SC-08 신규 수신호 등록 화면(관리자용)**: 경량 분류기(SVM) 채택으로 재학습 없는 실시간
