# 화면 목록 (Screen Inventory) v1

> 관련: 프로젝트 계획서 · 설계 문서 · 인터페이스 계약서
출처: 심기일전_시나리오초안 (사용자 시나리오 Happy Path / 예외 시나리오)을 화면 단위로 재구성
> 

> **이 문서 작성법**
화면 목록은 “웹페이지에 실제로 몇 개의 화면(또는 화면 상태)이 필요한가”를 정하는 첫 산출물입니다. 아래 순서로 작성하세요.
> 
> 1. **시나리오 문서의 “단계”를 하나씩 따라가며, 화면이 바뀌는 지점마다 새 화면으로 분리합니다.** (예: 시나리오의 1~9단계를 그대로 화면 후보로 나열)
> 2. **같은 레이아웃에서 상태만 바뀌는 경우는 별도 화면이 아니라 “화면 내 상태”로 묶습니다.** 예를 들어 시나리오 5번(정답)·6번(오답)은 둘 다 “수신호 시범/인식 화면” 위에 뜨는 오버레이일 뿐, 화면 자체가 바뀌는 게 아닙니다 → 아래 표에서도 하나의 화면(SC-04) 안에 정답/오답 상태로 정리했습니다.
> 3. **예외 시나리오(카메라 인식 실패, 중간 이탈 등)도 화면 후보에 반드시 포함합니다.** 예외 화면을 빼먹으면 나중에 개발 중간에 “이 상황엔 뭘 보여주지?”로 막히게 됩니다.
> 4. **각 화면마다 “다음 화면(전환 경로)”을 반드시 적습니다.** 이게 채워지면 자동으로 사용자 흐름도(User Flow)의 초안이 됩니다 — 다음 산출물로 바로 이어집니다.
> 5. **필수/부가를 구분합니다.** 계획서의 “포함 범위(필수)”와 “부가 기능(여유 시)” 구분을 그대로 따르세요. 부가 기능 화면은 먼저 자리만 잡아두고, 필수 화면부터 와이어프레임으로 넘어가면 됩니다.
> 6. 표를 다 채운 뒤 **팀 회의에서 “화면 개수가 5주 안에 만들 수 있는 수준인지”를 한 번 검토**하세요. 화면이 너무 많으면 2번 원칙(상태로 묶기)을 다시 적용해 줄이는 것을 권장합니다.

## 아직 팀이 정해야 할 것 (⚠️)

- **SC-04의 화면 분할 단위**: “수신호 시범”과 “카메라 인식”을 한 화면 안에서 동시에 보여줄지, 시범 먼저 보여주고 넘어가는 방식으로 분리할지 — 설계 문서의 파이프라인 확정과 함께 결정하면 좋습니다.
- **SC-08 이어서 하기 여부**: 시나리오 문서 원문에도 “재접속 시 이어서 진행 여부는 팀 논의 필요”라고 명시되어 있습니다. 세션 저장 기능 구현 여부를 이번 프로젝트 범위에 넣을지 먼저 결정하세요 (계획서 “포함/제외 범위”에도 반영 필요).
- **SC-09 관리자 메뉴 진입 방식**: 별도 비밀번호/URL로 구분할지, 학습자 화면과 완전히 분리된 별도 페이지로 만들지.
- **SC-10 사원증 인식 방식**: QR/태그 부착 방식 vs 사진 자체 인식 방식 — 확정 전까지는 화면만 자리 잡아두고 개발은 보류.
