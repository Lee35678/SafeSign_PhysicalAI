**판정 성능 5개**(KPI-1~5)는 오프라인으로 쟀다. 학습에 쓰지 않은 팀원 3명을 평가용으로 따로 촬영한 70테이크씩, 모두 210시도다. 판정에는 운영과 같은 3프레임 연속 동일 판정 규칙을 적용했다. 촬영 도구는 약 0.15초 간격으로 3장만 남기므로 초당 약 26프레임을 보는 운영보다 엄격하다. 모델은 공개 데이터로만 학습했고 자체 촬영분은 학습에 넣지 않았다. 느슨한 규칙(최빈값)으로 계산하면 KPI-1~5가 차례로 96.7% · 0.0% · 3.3% · 0.982 · 0건이 나오는데, 표에는 더 엄격한 3프레임 연속 값을 적었다.

**지연 2개**(KPI-6·7)는 2026-10-02에 모든 장치를 실물로 연결한 상태에서 온라인으로 쟀다. 팀원 1명이 7종을 13번씩 돌린 91시도이며 91시도 모두 첫 시도에 정답이 나왔다. 물리 피드백 지연은 09-30 회의 결정에 따라 반응 시작(장치가 명령을 받았다고 응답한 시점)을 기준으로 판정했고, 동작 완료 기준 값도 함께 적었다.

**판정 표기.** 7개 모두 점추정이 목표를 충족했다. 다만 팀 규칙(06 §2-1, 16 §5.7)에 따라 95% 구간이 목표선을 넘는 3개는 '잠정 달성'으로 적었다. 정답률(하한 91.5%)과 미판정률(상한 8.5%)은 구간이 목표선에 걸치고, 치명 오분류 0건은 정지 30시도뿐이라 95% 상한이 11.4%다. 오분류율 상한 1.8%와 이 구간들은 210시도를 서로 독립으로 볼 때의 값이며, 실제로는 3명 × 70시도로 묶여 있어 사람 간 차이는 반영되지 않는다(본문 §8).

## 과제와 접근방법

**과제 배경.** 산업 현장에서는 작업자마다 안전 수신호를 이해하고 표현하는 방식이 달라서 소통 오류가 사고로 이어질 수 있다. 2010~2019년 타워크레인 양중작업 재해 343건 중 45건(13.0%)이 신호체계 미준수에서 나왔다. 그런데 국내 타워크레인 신호수는 별도 자격 없이 8시간 특별교육만 받으면 되고, 그 교육도 이론 위주라 실기 평가가 없다. 영상 시청이나 인쇄물 위주의 기존 교육으로는 교육자가 학습자의 습득 정도를 객관적으로 판단할 수 없고, 학습자도 자기가 제대로 하고 있는지 알기 어렵다(본문 §1).

**요구사항.** ① 정답 자세를 보여준다. ② 학습자의 손을 판정한다. ③ 판정 결과를 장치 동작으로 돌려준다. ④ 교육자가 볼 기록을 남긴다.

**해결 방법.** 로봇 손(AI Hand)이 수신호를 시범하고, 카메라가 학습자의 손을 판정하고, 판정 결과를 주행 로봇(picar)과 micro:bit LED의 동작으로 되돌려 주는 닫힌 루프로 만들었다. 화면만으로는 수신호가 실제 장비를 움직인다는 감각을 주기 어렵다고 보고 물리 장치를 교육의 중심에 두었다.

인식에는 **MediaPipe 손 랜드마크 + SVM**을 썼다. 딥러닝 모델보다 학습 데이터가 적게 들고, RPi5에서 실시간으로 돌아가며, 판정 근거(관절 각도·거리)를 설명할 수 있기 때문이다(05 모델카드 §3). 딥러닝과는 연구로 한 번 비교했다. 같은 공개 데이터를 세션 단위로 나눠 딥러닝 모델(HandFormer-base EDL)과 비교한 결과, 분류 정답률은 거의 같았고(시험셋 97.28% 대 96.94%) 처음 보는 손을 거르는 능력은 SVM 방식이 앞섰다(시험 AUC 0.968 대 0.934). 딥러닝 모델은 연구로만 만들었고 운영은 SVM을 유지했다(본문 §5-5, 출처 `vision_research` 브랜치 `RESEARCH.md` §7-1).

**수신호와 학습 데이터.** 수신호 5종은 크레인작업표준신호지침(고용노동부고시)의 신호를 AI Hand가 만들 수 있는 손 모양으로 재해석한 시안이고, 후진·주의 2종은 자체 지정이다. 표준 신호는 팔 동작이라 그대로 재현한 것이 아니다(본문 §2). 학습 데이터는 공개 데이터셋 2종(27,735건)에서 손 모양만 빌려 왔다. 6종은 ASL 지문자 데이터셋(라이선스 ODbL)에서, 정지는 손가락으로 1~5를 세는 사진 데이터셋(라이선스 MIT)에서 가져왔고, 어느 쪽도 원래 뜻과는 관계가 없다.

## 최종 결과물

**완성 기능.** 회원가입·로그인부터 수신호 7종 시범·판정, 물리 피드백, 결과 집계, 수료증 발급까지 교육 전 과정이 동작한다.

| --- | --- |
| `services/vision` | 카메라 → 손 랜드마크 21점 → 특징 23차원 → SVM 판정 (τ 0.75 + 3프레임 연속) |
| `services/web` | 교육 진행 상태머신(SC-01~SC-07), 회원·결과 DB(Supabase), 시행 로그 CSV |

| `services/data` | 학습 데이터 변환·검증 |

**사용 방법.** RPi5에서 `bash scripts/rpi/start_all.sh`를 실행하면 서비스 4개가 함께 켜진다. 학습자는 브라우저에서 가입·로그인한 뒤 "교육 시작"을 누르고, 화면과 AI Hand 시범을 본 다음 **확인**(화면 버튼, Space 키, micro:bit A 버튼 중 하나)을 눌러 판정을 시작한다. 7종을 마치면 집계 화면과 수료증이 나온다.

**규모.** 보드 2대(RPi5 고정, RPi4B 주행), 서비스 6개, 수신호 7종, 자동 테스트 320건(web 124 · vision 78 · actuation 54 · picar 52 · portal 12, 10-03 기준 전부 통과).

## 주요 결과와 근거

**시험 수치**

- 오프라인 210시도 중 **200회 정답**(95.2%), 오분류 0회, 미판정 10회.
- 사람별 최저 **94.3%**(ext02·ext03), 최고 97.1%(ext01)로 세 사람 차이는 2.8%p다.
- **오분류는 세 사람 모두 0%였다.** 다른 신호로 잘못 읽은 경우가 한 번도 없었다.
- 학습에 쓰지 않은 팀원 3명의 정답률(95.2%)은 공개 데이터 교차검증 값(세션 단위 5겹, 88.68%)보다 높았다. 두 값은 데이터가 달라(ASL 사진 대 안내를 보고 수행한 자세) 바로 비교하기 어렵고, 공개 데이터에 애매한 자세가 더 많은 것이 유력한 이유로 보인다(12 §8-3). 자체 촬영분은 학습에 넣지 않았다.
- 온라인 91시도에서 판정 지연 P95는 **0.046초**, 물리 피드백 반응 시작 P95는 **0.089초**였다. 장치 응답 실패는 0건이었다.

**사용자 검토.** 실사용 시험에서 사용성 문제 **5건**을 찾았고 모두 고쳤다(본문 §6). 예를 들어 "AI Hand를 보기도 전에 오답이 떴다"는 문제는 확인 버튼을 넣어(CR-07), "틀리면 다음으로 안 넘어간다"는 문제는 시도를 3회로 제한하고 판정마다 10초 제한을 둬서(CR-08) 해결했다. 두 수정 모두 09-29 실물 재시험을 통과했다. 로봇 손 시범이 헷갈린다는 1건은 AI Hand를 교체해 해결했다. 외부 학습자(현장 작업자) 의견은 아직 받지 못했다. 평가에 참여한 3명은 모두 팀원이다.

## 계획 대비 변경

초기 계획에서 바뀐 결정은 **12건**이다(CR-01~CR-12, 본문 §3-2). 성격별로 묶으면 다음과 같다.

1. **하드웨어 구조.** picar를 RPi5에서 떼어 별도 보드로 옮겼다(CR-01). picar가 움직이면 거기 달린 카메라도 함께 움직여 판정을 할 수 없었기 때문이다.
2. **수신호 정의.** 사람이 따라 하기 어렵거나 학습 데이터가 없는 손모양 2종을 바꿨다(CR-03·04). `negative`(기타)는 학습 클래스에서 빼고 τ 미달 미판정으로 처리했다(CR-05).
3. **교육 흐름.** 시범을 보기 전에 오답 처리되던 문제는 확인 버튼으로(CR-07), 끝나지 않던 시도는 3회 상한과 10초 제한으로(CR-08) 해결했다.
4. **범위와 측정 기준.** picar 원격 조종 모드는 넣지 않았다(CR-11). 물리 피드백 지연은 반응 시작 기준으로 판정하고 완료 기준을 함께 적기로 했다(CR-12).

## 한계

- **지연의 측정 구간이 좁다.** 판정 지연은 연속 판정을 확정한 마지막 프레임 1장의 처리 시간만 기록한다. 손을 멈춘 시점부터 계산한 보수적 상한은 P95 0.335초다. 240fps 슬로모션 영상으로 7시도를 직접 세어 보니 손을 멈춘 뒤 반응 시작까지 0.14~0.24초, 동작 완료(picar 주행 제외)까지 약 1.11~1.24초로 모두 목표 안이었다. 다만 영상 대조는 7시도뿐이다.
- **온라인 측정은 팀원 1명, 91시도다.** web 로그가 미판정을 기록하지 않아 온라인 미판정률은 낼 수 없다. 판정 성능의 공식 값은 오프라인 210시도를 쓴다.
- **정답률과 미판정률의 신뢰구간이 목표선에 걸친다**(정답률 하한 91.5%, 미판정률 상한 8.5%).
- **외부 학습자 의견을 받지 못했다.** 평가 데이터는 팀원 3명의 것이다.
- **시연 환경은 네이티브 실행만 검증했다.** Docker는 개발 PC mock과 CI에만 쓴다(CR-10).

# 본문

## 1. 배경과 사용자 문제

**신호는 법으로 정하게 되어 있는 안전 수단이다.** 산업안전보건기준에 관한 규칙 제40조는 양중기를 쓰는 작업, 유도자를 배치하는 작업, 중량물을 2명 이상이 함께 운반하는 작업 등에서 사업주가 일정한 신호방법을 정하고 운전자와 근로자가 그 신호를 따르도록 한다[1]. 타워크레인 신호업무는 특별교육 대상이고, 교육 내용에 "신호방법 및 요령에 관한 사항"이 들어 있다[2].

**신호를 제대로 하지 못하면 사고로 이어진다.** 2010~2019년 타워크레인 재해 437건 가운데 343건(78.5%)이 양중작업 중에 일어났고, 그중 45건(13.0%)은 신호체계 미준수가 원인이었다. 세부 원인으로는 신호방법 미숙지, 신호 순서 미준수, 신호 내용 착각이 꼽혔다[3]. 2020년 이동식 크레인 붐 해체작업 사망사고에서는 별도로 정한 기준 없이 관행대로 신호를 주고받은 것이 원인 중 하나로 지적됐다[4]. 2023년 크레인·타워크레인·이동식크레인에 의한 사망자는 23명으로, 근로감독관이 조사한 사망재해 564명의 4.1%다[5].

**지금의 신호 교육은 이론 위주이고 실기 평가가 없다.** 국내에서 타워크레인 신호수는 별도 자격 없이 사업주가 실시하는 8시간 이상의 특별교육만 받으면 된다. 미국(NCCCO)·영국(CPCS)·일본은 실기시험으로 신호 역량을 확인한다[3]. 같은 연구의 현장 인터뷰(9명)에서는 현장 관리자가 이론 위주로 가르쳐 이해하기 어렵다는 의견과 실습 없이 투입돼 위험한 순간이 있었다는 의견이 나왔다. 설문(56명)에서는 교육 방법으로 실습 위주의 실기 시험을 이론·실기 병행 시험보다 중요하게 평가했다(AHP 가중치 0.69 대 0.31)[3]. 크레인 수신호 표준(KS B ISO 16715, 27개 동작)이 있어도 현장마다 용어와 해석이 달라 운전원과 신호가 맞지 않는다는 지적도 있다[3].

**기존 교육 방식 비교.** 안전 수신호를 배울 수 있는 기존 방식은 다음과 같다. 산업 수신호를 직접 해 보고 그 자리에서 맞았는지 판정받는 교육 방식은 찾지 못했다.

| 방식 | 할 수 있는 것 | 부족한 것 |
| --- | --- | --- |
| 인터넷 교육[7] | 언제든 강의를 들을 수 있다 | 손으로 신호를 해 볼 수 없다 |
| 리플릿·매뉴얼[8] | 신호 동작을 그림으로 보여 준다 | 내가 맞게 하고 있는지 확인할 수 없다 |
| 강사 대면 실습 | 강사가 보고 고쳐 준다 | 안전보건공단 교육 포털에서 수신호 실습만을 다루는 과정은 찾지 못했다(2026-10 기준)[7] |
| VR 체험 교육[6] | 몰입과 상호작용. 한 제조업체 이수자 1,350명 설문에서 이해도·만족도 평균이 기존 온라인 교육보다 12% 안팎 높았다 | 위험 상황을 보고 느끼는 방식이라 학습자 동작이 맞았는지는 판정하지 않는다. 조사 시기·문항이 달라 효과를 입증한 것은 아니다 |
| 수어 학습 앱[9] | 카메라로 손동작이 맞는지 확인하고 학습 기록을 남긴다 | 수어를 다루며 산업 수신호는 다루지 않는다 |

SafeSign은 이 빈자리, 곧 수신호를 직접 해 보고 그 자리에서 판정받는 실습을 채우려는 교육 키트다. 안전보건공단의 교육 인정을 받기 전에는 법정 교육을 대신하지 않고 보조 도구로 쓴다.

**사용자와 문제**

| 사용자 | 문제 |
| --- | --- |
| 신입·현장 작업자 | 수신호를 본 적이 있는지와 실제로 할 수 있는지를 구분해 확인할 방법이 없다 |
| 안전 교육자 | 누가 어떤 수신호에 약한지 숫자로 알 수 없다 |

**기대 변화.** 습득 속도와 정확도가 오르고, 소통 오류로 인한 사고가 줄고, 학습자별로 약한 수신호를 알 수 있고, 기록을 바탕으로 교육 내용을 고칠 수 있다.

## 2. 목표와 범위

**목표.** 안전 수신호 7종을 시범, 따라 하기, 판정, 물리 피드백으로 이어지는 닫힌 루프 안에서 반복 학습하게 하고, 교육자가 쓸 수 있는 정량 기록을 남긴다.

**KPI.** F25 요약본의 7개 지표(01 프로젝트계획서 §목표와 KPI).

**범위에 넣은 것**

- 수신호 7종: 정지 · 서행 · 좌회전 유도 · 우회전 유도 · 확인/완료 · 후진 · 주의. 앞의 5종은 크레인작업표준신호지침(고용노동부고시)의 신호를 손 모양으로 재해석한 시안이고 후진·주의는 자체 지정이다. 표준 신호는 팔 동작이라, 정지·좌회전·우회전은 표준과 비슷한 수준이고 서행·확인/완료는 표준 동작과 다르다(02 설계문서 §4-1).
- 학습 데이터: 공개 데이터셋 2종 27,735건. ASL 지문자 데이터셋 combinedasldatasets(ODbL)에서 6종을, 손가락 세기 데이터셋 natural-finger-counting-dataset-1-5(MIT)에서 정지를 가져왔다. 지문자나 숫자의 뜻이 아니라 손 모양만 빌려 썼다(04 데이터셋명세서 §3-1·§5).
- 손의 **정지 자세** 한 장면 판정 (연속 동작은 판정하지 않음)
- 교육 진행 화면 SC-01~SC-07, 회원·결과 DB, 수료증

**범위에서 뺀 것과 이유**

| 뺀 것 | 이유 |
| --- | --- |
| 연속 제스처·동작 추적 | 정지 자세 판정만으로 교육 목적을 이룰 수 있고, 연속 동작은 데이터와 학습 비용이 크게 늘어난다 |
| 수신호 등록·관리자 화면 | 교육용 고정 커리큘럼 7종이면 충분하다 (03 §6) |
| 중간 이탈 후 이어하기 | 교육 1회가 약 5분으로 짧아 세션 복구에 드는 복잡도가 이득보다 크다 (CR-06) |
| picar 원격 조종 모드 | 교육 루프에 필요 없는 선택 기능이고, W4 일정은 냉각 대책과 KPI 실측이 먼저였다 (CR-11) |

## 4. 최종 결과물

구성과 사용 방법은 F25 요약본 "최종 결과물"에 적었다. 여기서는 판정과 피드백이 이어지는 방식을 보충한다.

**판정 파이프라인**

```text
카메라 → MediaPipe 손 랜드마크 21점 → 좌우손 통일·정규화 → 특징 23차원(관절 각도·거리)
      → SVM(RBF) → 클래스 확률 → τ(0.75) + 소속 게이트 + 3프레임 연속 → 판정 확정
```

**물리 피드백.** 판정이 확정되면 picar(주행·LED), micro:bit(O/X LED), AI Hand 순서로 명령을 보낸다. 이 순서는 09-28에 바꾼 것이다. 그전에는 AI Hand 명령을 먼저 보내서 picar와 micro:bit가 약 0.85초 늦게 반응했다.

**AI Hand는 시범 전용이다.** 판정 뒤 보내는 정답 자세와 재시범은 시범과 같은 제스처라서, 시범을 마친 손은 판정 뒤에 움직이지 않는다. 정답·오답은 micro:bit O/X와 picar가 알린다. 정답 자세를 다른 동작으로 바꾸면 서보 동작 수가 늘어나므로 이대로 두기로 했다. 시행 로그의 `aihand_ms`(약 0.88초)는 손이 실제로 움직인 시간이 아니라 펌웨어가 손가락 5개에 150ms 간격으로 명령을 내리는 시간이다.

**기록.** 회원 DB에는 회차별·수신호별 결과가 쌓이고, KPI 계산용 시행 로그는 CSV로 따로 남는다. 시행 로그 한 행에는 판정 지연, 장치별 응답 시간, 반응 시작·완료 지연이 함께 기록된다.

### 5-5. 분류기 비교 (연구)

딥러닝 모델이 운영 방식(SVM + 소속 게이트)을 대신할 수 있는지 확인하려고, 이동혁이 09-23에 연구 브랜치(`vision_research`, 커밋 `b0bd7c0`)에서 두 방식을 비교했다. 공개 데이터만 썼고 학습·검증·시험을 세션 단위로 나눴으며, 자체 촬영 데이터는 쓰지 않았다. 딥러닝 쪽은 HandFormer-base에 EDL(판정과 함께 불확실성을 내도록 학습하는 방식)을 적용한 모델 5개의 앙상블이고, Colab에서 178분 학습했다. 두 방식은 같은 분할에서 같은 규칙으로 비교했다.

| 항목 | SVM + 소속 게이트 p10 (운영) | HandFormer-base EDL ×5 (연구) |
| --- | --- | --- |
| 시험 정답률 | 97.28% | 96.94% |
| 처음 보는 손 거르기 AUC (검증 / 시험) | **0.948 / 0.968** | 0.922 / 0.934 |
| 시험 정상 오거부 · 미지 차단 (각자의 기준선) | 12.6% · 95.7% | 4.1% · 59.3% |

> 출처는 `RESEARCH.md` §7-1이다. 처음 보는 손 거르기 AUC는 7종 중 한 종을 학습에서 빼고, 뺀 종을 처음 보는 손으로 넣어 정상 자세와 얼마나 잘 가르는지 잰 값이다. 1에 가까울수록 잘 거른다. 정상 오거부와 미지 차단은 두 방식이 각자 다른 기준선에서 잰 값이라 서로 바로 비교하지 않는다.

**결론.** 분류 성능은 사실상 같고, 처음 보는 손을 거르는 능력은 운영 방식이 검증·시험 모두에서 앞섰다. AUC 차이(약 0.03)는 연구 안에서 설정만 바꿔도 생기는 흔들림(±0.015)보다 크다. 그래서 운영은 SVM을 유지했다. 딥러닝 모델은 연구로만 만들었고 운영에 쓰지 않았으며, 연구 브랜치는 `dev`에 병합하지 않았다.

**정답률 숫자 읽는 법.** 이 표의 SVM 정답률 97.28%는 세션 단위로 한 번 나눈 시험셋의 값이다. 요약본의 88.68%는 같은 공개 데이터를 세션 단위 5겹 교차검증으로 잰 값이다. 분할 방식이 달라 두 값을 섞어 비교하지 않는다(§8-1).

## 6. 사용자 의견

외부 학습자(현장 작업자)에게서는 아직 의견을 받지 못했다. 평가에 참여한 3명은 팀원이다. 아래는 실사용 시험 중 관찰한 사용성 문제와 그 처리 결과다.

| 관찰한 문제 | 처리 |
| --- | --- |
| "AI Hand를 보기도 전에 오답이 떴다" | 확인 버튼 도입 (CR-07) |
| "틀리기만 하면 다음으로 안 넘어간다" | 시도 상한 3회 + 10초 제한 (CR-08) |
| "손을 잠깐 내렸는데 카메라 실패 화면으로 넘어간다" | 시범 단계에서는 손 미검출을 세지 않도록 수정 |
| "카메라 실패 화면에서 재시도를 눌러도 안 돌아간다" | 재시도를 누르면 시범 단계로 돌아가 AI Hand가 다시 시범하도록 재작성 |
| "좌회전인지 후진인지 로봇 손만 봐서는 모르겠다" | AI Hand 교체로 해결 |

**W5 보완 계획.** 시연·발표 자리에서 참관자 3~5명이 5분 동안 체험한 뒤 세 가지를 묻는다. 무엇을 하라는지 알았는가, 틀렸을 때 왜 틀렸는지 알았는가, 다시 해 보고 싶었는가.

## 7. 달성 · 부분 · 미달 판정

**종합 판정: 달성 (KPI 7개 중 3개는 잠정 달성)**

| 구분 | 내용 |
| --- | --- |
| 달성 | KPI 7개(KPI-1~7)가 모두 점추정으로 목표를 충족했다. 그중 정답률·미판정률·치명 오분류 3개는 95% 구간이 목표선을 넘어 잠정 달성이다. 평가 210시도에서 정지를 포함한 어떤 신호도 다른 신호로 읽지 않았다(오분류 0%, 치명 오분류 0건). 전 구간 통합 동작도 실물에서 확인했다 |
| 부분 | KPI 밖 항목인 사용자 의견: 외부 학습자의 의견은 아직 받지 못했다 |
| 미달 | 없음 |

**판정에 붙는 조건**

- 정답률과 미판정률은 점추정으로 목표를 충족하지만 95% 신뢰구간이 목표선에 걸친다(정답률 하한 91.5%, 미판정률 상한 8.5%).
- 치명 오분류 0건은 정지 30시도에서 나온 값이라 95% 상한이 11.4%다. 상한을 3% 아래로 내리려면 정지만 약 125시도가 필요하다.
- 지연 2개는 P95의 95% 상한까지 목표 안이지만 기록된 값이 재는 구간은 계획서 정의보다 좁다(§5-3). 슬로모션 7시도로 센 값(반응 시작 0.14~0.24초, picar 주행을 뺀 완료 약 1.11~1.24초)도 목표 안이다.
- 판정 성능은 팀원 3명, 지연은 팀원 1명이 측정 대상이었다. 온라인 91시도의 판정 성능(정답 100%)은 미판정을 기록하지 않아 참고값으로만 쓴다.

## 8. 한계와 향후 과제

### 8-1. 한계

| 한계 | 내용 | 영향 |
| --- | --- | --- |
| 지연 측정 구간 | 판정 지연은 마지막 프레임 1장의 처리 시간만 기록한다 | 손을 멈춘 시점부터의 지연은 슬로모션 7시도 대조로만 확인했다(반응 시작 0.14~0.24초, 완료 약 1.11~1.24초) |
| 평가 규모 | 오프라인 210시도(3명), 온라인 91시도(1명) | 오분류율 0%는 "95% 신뢰로 1.8% 이하", 치명 오분류 0건은 "11.4% 이하"로 읽어야 한다. 이 구간은 시도를 서로 독립으로 본 값이라 사람 간 차이(3명)는 반영되지 않는다. 정답률·미판정률 구간이 목표선에 걸친다 |
| 온라인 미판정 미기록 | web 로그가 τ 미달·분포 밖 판정을 기록하지 않는다 | 온라인 미판정률을 낼 수 없어 오프라인 값만 쓴다 |
| 기울인 손 과차단 | 미판정 10건 중 7건이 오른쪽으로 기울인 손 | 후진 미판정 20%, 확인_완료 10% |
| 분류기 비교 범위 | 딥러닝 모델(HandFormer-base EDL) 1종과만 비교했다(§5-5). 랜덤포레스트·kNN과는 비교하지 않았다 | 비교한 딥러닝 모델보다 처음 보는 손을 잘 거른다는 것까지만 말할 수 있다 |
| 비교 분할 방식 | 분류기 비교는 세션 단위로 학습·검증·시험을 한 번 나눈 결과이고, 05 모델카드의 기준값(88.68%)은 세션 단위 5겹 교차검증이다 | 같은 공개 데이터의 SVM 정답률이 97.28%와 88.68%로 다르게 나온다. 각각 조건을 붙여 읽어야 하고 서로 비교하지 않는다 |
| 게이트의 정상 자세 거부 | 운영 게이트(p10)는 공개 시험셋에서 정상 자세의 12.6%(검증셋 20.0%)를 거부했다. 게이트 기준을 정할 때 자체 촬영(1명, 정상 105건)에서 본 2.9%와 차이가 크다 | 연구는 공개 데이터의 정상 자세가 원래 고르지 않은 사진이라는 점을 이유로 든다. 실제 초보 학습자가 어느 쪽에 가까운지는 아직 모른다. 최종 평가 210시도의 미판정은 4.8%였고 전부 이 게이트에서 나왔다 |
| 외부인 평가 없음 | 평가자 3명이 모두 학습에 쓰지 않은 팀원. 외부인 1명 촬영분은 손 모양 오류로 폐기(§5-1) | 처음 배우는 사람의 성능과 현장 적합성은 검증하지 않았다 |
| 표준과의 차이 | 수신호 5종은 크레인 표준 신호(팔 동작)를 손 모양으로 재해석한 시안 | 서행·확인/완료는 표준 동작과 다르다. 현장 표준 신호 그대로를 가르치는 교육은 아니다 |
| 실행 환경 | 네이티브 실행만 검증, Docker는 mock·CI 전용 | 다른 환경으로의 이식은 검증하지 않았다 |

| 표준 정합성 | 현장 안전 교육 담당자와 손 모양 시안을 검토하거나, 표준 팔 동작을 인식하는 방식(자세 추정)을 검토한다 |
| picar 원격 조종 모드 | 이번 범위에서 뺀 선택 기능 (CR-11) |
| 연속 동작 인식 | 이번 범위에서 뺀 연속 제스처·동작 추적 |
| 운영 전 조건 | 개인정보(이메일·이름·소속) 삭제 절차, `service_role` 키 폐기, 서보 반복 사용 상한 확인 |
| 운영 자동화 | 보드가 재부팅되거나 서비스가 멈추면 자동으로 다시 띄우는 systemd 설정(`scripts/rpi/systemd/`)을 만들었지만 실물 검증 전이다. 시연은 지금처럼 tmux 기동 스크립트로 한다. GitHub Actions 자동 테스트(`.github/workflows/ci.yml`)는 저장소 설정에서 허용한 뒤 첫 실행이 남았고, docker compose 통합 테스트 단계는 아직 없다 |
| 보안 보강 | 회사 사이트는 로그아웃이나 비밀번호 재설정 뒤에도 기존 로그인 쿠키가 최대 8시간 유효하다. 서버에서 세션을 무효화하게 바꾼다. 교육장 화면의 POST 요청에는 요청 출처를 확인하는 헤더(CSRF 방지)를 추가한다 |
| 코드 구조 정리 | 900~1,300줄짜리 파일 3개(교육장 상태머신·회원 모듈·화면 스크립트)를 기능별로 나눈다. 여러 곳에 따로 적힌 수신호 정의(이름·손가락 패턴 등)는 한 곳에서 내려받게 한다. 지금은 자동 테스트로 서로 같은지만 검사한다 |
| 피드백 대기 시간 정렬 | 교육장이 actuation 응답을 기다리는 시간(명령 1.5초, 결과·진행 0.5초)이 actuation이 micro:bit 회신을 기다리는 시간(2.0초)보다 짧다. 맞추면 물리 피드백 지연이 달라지므로 KPI 재측정과 함께 한다 |
| MediaPipe 버전 통일 | 학습 데이터 추출 도구(`services/data`, 0.10.14 고정)와 실행 서비스(`services/vision`, 1.x)의 버전 지정이 다르다. 맞추려면 랜드마크를 다시 추출하고 재학습한 뒤 KPI를 다시 재야 한다 |
