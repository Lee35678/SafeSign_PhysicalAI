## 2. 혼동행렬 (Confusion Matrix)

> 테스트 기록의 시행 로그를 집계하여 작성. 특히 “정지” 신호가 다른 신호로 오판정된 사례(치명 오분류)는 별도 강조.
> 

*(표/이미지 삽입 예정)*

> **만드는 법:** “정답 클래스”를 행, “예측 클래스”를 열로 하는 표를 만들고, 각 칸에 해당하는 시도 건수를 채웁니다(파이썬이면 `sklearn.metrics.confusion_matrix` 사용 가능). 대각선(정답 클래스=예측 클래스)이 많을수록 좋은 모델입니다. “정지” 행에서 대각선이 아닌 칸에 숫자가 있으면 그게 치명 오분류이므로 빨간색 등으로 눈에 띄게 표시하세요.
> 

## 3. 지연 분포

> 판정 지연, 물리 피드백 지연 각각의 분포(히스토그램) — P95 계산 근거 명시
> 

*(그래프 삽입 예정)*

> **만드는 법:** 테스트 기록의 “판정지연(ms)”·“물리피드백지연(ms)” 열 값을 모아 히스토그램(막대그래프)을 그립니다. P95는 값을 오름차순 정렬했을 때 “하위 95% 지점”의 값입니다 — 예를 들어 100개 시도를 정렬했을 때 95번째로 작은 값. 엑셀의 `PERCENTILE` 함수나 파이썬 `numpy.percentile(data, 95)`로 계산 가능합니다.
>

> 

| 대상 | 정답률 | 비고 |
| --- | --- | --- |
| 팀원 (train/val) |  |  |
| 외부인 (test) |  |  |

> **작성법:** 두 정답률의 차이가 크면(예: 팀원 98% vs 외부인 75%) 과적합이 실제로 발생했다는 뜻입니다. 이 경우 원인(데이터 다양성 부족 등)과 대응(추가 데이터 수집, 정규화 강화 등)을 함께 적으세요. 차이가 크지 않다면 subject-wise split이 잘 작동했다는 근거로 그대로 기재하면 됩니다.
