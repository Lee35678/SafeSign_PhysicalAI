# 시연영상 제작 제안서 (초안)

**팀명**: 심기일전 · **작성**: 조은수 · **초안**: 2026-09-30 (마감 10/1 저녁) · **완성 목표**: 2026-10-06 저녁(시연을 위해 모이기 전까지)
**다루는 것**: ① 어떤 위치·각도로 촬영할지 ② 시연 기물을 어떻게 배치할지 ③ 시연자가 어떤 흐름으로 진행할지

> 🟡 **초안**: 거리·시간 수치는 문서의 실측값에서 가져온 것과 **제안값**을 구분해 적었다(제안값은 "제안"으로 표시).
> 제안값은 모이는 날 리허설 1회로 확인하고 완성본에서 확정한다.

## 1. 영상 개요

| 항목 | 내용 |
| --- | --- |
| 목적 | 발표(5분)에서 말로만 설명한 **닫힌 루프**(시범 → 따라 하기 → 판정 → 물리 피드백 → 재시도)를 실제 장비로 보여준다 |
| 길이 | **약 2분 30초 ~ 3분** (제안) — 7종 전부를 같은 길이로 보여주지 않고, 대표 3종만 자세히 보여준 뒤 나머지는 빠르게 |
| 꼭 보여줄 장면 | ① AI Hand 시범 + 화면 예시 사진 ② 확인 버튼(Space) → 판정 ③ 정답 → micro:bit O + picar 주행·LED ④ **오답 → X + AI Hand 재시범 → 재도전 정답** ⑤ SC-05 결과("첫 시도 정답")·SC-06 수료증 |
| 소리 | 시스템에는 소리가 없다(micro:bit 부저는 BLE 충돌로 배제, `11_하드웨어설계서` §4.7) → **자막 + 배경음악**, 필요하면 내레이션 후녹음 |

## 2. 시연 기물

| 기물 | 역할 | 비고 |
| --- | --- | --- |
| Raspberry Pi 5 + Pi Camera Module 3 | 학습자 손 촬영·판정·web·AI Hand 명령 | 카메라는 CSI 케이블(15→22핀) — 예비 케이블 지참 |
| AI Hand (micro:bit v2 + StartbitV2 내장) | 수신호 시범, LED O/X, 버튼 A 확인 | — |
| picar (Raspberry Pi 4B 탑재) | 정답 시 수신호 의미대로 주행 + LED 4개 | 배터리 단일 계통, **USB-C 동시 연결 금지** |
| 시연 PC + 모니터 | web 교육 화면(SC-01~07), 키보드 Space로 확인 | RPi5와 UTP 직결 |
| 조명 | 손이 잘 보이게 | 평범한 실내 조명 + 단순 배경(데이터 촬영 조건과 같게, `04_데이터셋명세서`) |
| 촬영용 스마트폰 3~4대 + 삼각대 | §4 카메라 A~D | 팀원 폰 사용(제안) |
| 멀티탭·케이블 정리용 테이프 | 화면에 케이블이 덜 보이게 | |

## 3. 기물 배치

### 3.1 배치도 (위에서 본 모습)

```
                    ─────────────── 벽 (단색 배경) ───────────────

   ┌─ 테이블 ──────────────────────────────────────┐
   │  [모니터]        [RPi5 + Pi Camera]   [AI Hand] │   ◀── (B) AI Hand 측면 30°
   │  (학습자 왼쪽)      카메라는 학습자 쪽을 향함   (카메라 화각 밖) │
   └───────────────────────────┬──────────────────┘
                               │ 약 50~70cm (제안)
                               ▼
                         [학습자 손]                        (A) 전경 — 학습자 오른쪽 앞 사선 45°
                         [학습자 = 시연자]                        ↖
                               ▲
                    (C) 어깨 너머 — 학습자 뒤

   ┌─ 바닥: picar 주행 구역 (제안 1.5m × 1.5m, 리허설로 확정) ─┐
   │  [picar] ──▶  전진 · 좌/우회전 · 후진 여유 공간             │   ◀── (D) 바닥 높이 로우앵글, 측면
   │  관찰자: 배터리 스위치 옆                                   │
   └──────────────────────────────────────────────────────────┘
```

> 테이블 위 좌→우 순서(모니터 · 카메라 · AI Hand)는 예시다. 지켜야 할 것은 §3.2 원칙 1~4(AI Hand는 화각 밖,
> 카메라는 손 높이 정면, 역광 금지, 모니터는 고개만 돌려 보이는 곳)이다.

### 3.2 배치 원칙

| # | 원칙 | 이유 |
| --- | --- | --- |
| 1 | **AI Hand는 Pi Camera 화각 밖**에 둔다 | 로봇 손이 카메라에 잡히면 학습자 손으로 인식될 수 있다. 시작 전 "손을 치우고 AI Hand를 정지 자세로 둔 채 손 미검출이 나오는지" 확인한다(`16_통합테스트_KPI_CI` 시행 당일 절차 6) |
| 2 | 카메라는 학습자 손 높이, 정면 | 데이터가 정면·±15° 기울임으로 학습됐다(`04` 촬영 변인). 거리 50~70cm는 **제안값** — 리허설에서 판정이 안정적인 거리로 확정 |
| 3 | 역광·강한 그림자 금지 | 극단적 역광·어두운 공간은 범위 밖(`01_프로젝트계획서` 제외 범위). 창문을 등지고 서지 않는다 |
| 4 | 모니터는 학습자가 **고개만 돌려** 볼 수 있는 위치 | 학습자가 화면(예시 사진·결과)과 AI Hand를 번갈아 봐야 한다. 모니터를 보느라 손이 카메라 밖으로 나가면 SC-04가 뜬다 |
| 5 | picar는 테이블 **아래 바닥**, 주행 방향으로 여유 공간 | 한 번 명령에 약 2초 주행 후 자동 정지(`MOTION_DURATION_S` 2.0초), 속도는 서행 20 · 회전·후진 40(`13_picar_하드웨어_검증리포트` §4.5). 벽·사람 쪽으로 향하지 않게 |
| 6 | 배터리 스위치는 관찰자 손이 닿는 곳 | 비상정지는 배터리 스위치 OFF(`16` 안전·복구) |
| 7 | 케이블은 테이블 뒤로 | 전경(A)에서 깔끔하게. RPi5↔PC UTP, RPi5 전원만 보이면 된다 |

## 4. 촬영 위치와 각도

카메라 4대 동시 촬영 + PC 화면 녹화 1개(제안). 폰이 부족하면 같은 장면을 2회 찍어 편집으로 합친다.

| 카메라 | 위치 · 각도 | 담는 것 | 쓰는 장면 |
| --- | --- | --- | --- |
| **A 전경** | 학습자 오른쪽 앞 **사선 45°**, 삼각대, 눈높이, 광각 | 학습자·AI Hand·모니터·picar 구역이 한 화면 — "하나의 루프"임을 보여주는 기준 컷 | 인트로, 장면 전환, 전체 흐름 |
| **B AI Hand 클로즈업** | AI Hand **측면 30°**, 손 높이, 30~40cm | 손가락 시범 동작, micro:bit LED O/X | 시범·재시범, 판정 결과 |
| **C 어깨 너머** | 학습자 **뒤쪽 어깨 너머**, 약간 위에서 | 학습자 손동작 + 모니터 화면이 함께 — "따라 하면 화면이 판정" | 확인 버튼 → 판정 순간 |
| **D picar 로우앵글** | 바닥 가까이(**약 20cm 높이**, 제안), 주행 방향 **측면** | 바퀴 움직임·LED 색·자동 정지 | 정답 후 물리 피드백 |
| **화면 녹화** | 시연 PC에서 브라우저 화면 녹화 | SC-02~SC-07 화면을 선명하게 | 화면 인서트(예시 사진, 오버레이, 수료증) |

- 모든 카메라 **가로(16:9)**, 같은 해상도로. 촬영 시작 때 한 번 박수 치거나 화면에 시각을 띄워 편집 싱크를 맞춘다(제안).
- 카메라 A는 처음부터 끝까지 끊지 않고 찍는다 — 다른 컷이 실패해도 A만으로 영상이 성립하게.

## 5. 시연 흐름 (콘티)

시연자(학습자) 1명이 SC-01부터 끝까지 한 번에 진행한다. 7종 중 **정지 · 서행 · 좌회전 유도** 3종을 자세히,
나머지 4종은 빠르게 보여준다.

| # | 시간(제안) | 시연자 동작 | 화면·장치 반응 | 주 카메라 | 자막(안) |
| --- | --- | --- | --- | --- | --- |
| S0 | 0:00–0:10 | — (장비 전경) | — | A | "현장마다 다른 수신호, 따라 할 수 있는지 확인할 방법이 없다" |
| S1 | 0:10–0:20 | 시작하기 → 교육 시작 클릭 | SC-01 → SC-02(7종 목록) → SC-03 | 화면녹화 → A | "AI Hand와 함께하는 안전 수신호 교육" |
| S2 | 0:20–0:45 | **정지**: AI Hand 시범을 보고 Space → 다섯 손가락 펴기 | AI Hand 시범 + 예시 사진 → 판정 → **정답** → micro:bit **O**, picar **정지 + 적색 LED** | B → C → B → D | "① 시범 → ② 확인 → ③ 판정 → ④ 로봇 피드백" |
| S3 | 0:45–1:25 | **서행 (오답 시연)**: 일부러 다른 수신호(예: 주의)를 1초 이상 유지 → 재시범 보고 Space → 검지+중지 | **오답** → micro:bit **X** + AI Hand **재시범** + 사진 → 재도전 **정답** → picar **감속 주행 + 황색 LED 점멸** | C → B → C → D | "틀리면 다시 보여준다 — 탈락 없이, 시도 횟수는 기록" |
| S4 | 1:25–1:45 | **좌회전 유도**: 엄지+검지 | 정답 → picar **좌회전 + 좌측 황색 LED** | C → D | "수신호 의미대로 picar가 움직인다" |
| S5 | 1:45–2:05 | 우회전 유도 · 확인/완료 · 후진 · 주의 | 각각 정답 → picar 동작 | A (빠른 컷, 2배속 제안) | — |
| S6 | 2:05–2:25 | 결과 확인 → 수료증 발급받기 | SC-05 "첫 시도 정답 6 / 7"(서행만 X) → SC-06 수료증 | 화면녹화 | "교육자는 어떤 수신호를 한 번에 못 맞혔는지 본다" |
| S7 | 2:25–2:40 | — | 시스템 구성 그림(발표자료 4장 재사용) | 그래픽 | "Pi Camera + MediaPipe + SVM · micro:bit BLE · picar Wi-Fi" |

**선택 장면** (시간이 남으면): 7종이 아닌 손모양(예: 주먹을 비튼 모양)을 보여 **"다른 수신호를 하고 계세요"** 보류 안내,
또는 micro:bit **버튼 A**로 확인하는 장면.

### 5.1 시연자 동작 요령

- 확인(Space)을 누른 뒤 **손을 카메라 앞에 올리고 멈춘다** — 판정은 손이 멈춘 상태에서 3프레임 연속으로 확정된다.
- 오답 시연(S3)은 **틀린 손모양을 1초 이상 유지**해야 오답으로 확정된다(1초 미만은 손을 올리는 과도 자세로 보고 무시).
- 판정 중 손을 **약 5초 이상** 카메라 밖에 두면 SC-04("카메라 위치를 조정해주세요")로 넘어간다 — 화면을 보느라 손을 내리지 않는다.
- 수신호 사이에는 정답 연출(picar 약 2초 주행)이 끝나고 **확인 버튼이 다시 나올 때까지** 기다린다.

## 6. 당일 역할과 진행 순서

| 역할 | 하는 일 | 담당(안) |
| --- | --- | --- |
| 시연자(학습자) | §5 흐름대로 진행 | 【미정】 |
| 관찰자 | picar 옆, **배터리 스위치 담당**(비상정지), AI Hand·LED 육안 확인 | 【미정】 |
| 촬영 | 카메라 A·D 담당(B·C는 삼각대 고정) + 화면 녹화 시작/종료 | 【미정】 |
| 진행·기록 | 기동/종료 스크립트, 테이크 번호·실패 기록 | 【미정】 |

**진행 순서**

1. 배치(§3) → AI Hand 화각 밖 확인 → 조명 확인
2. 기동: RPi5에서 `bash scripts/rpi/start_all.sh` → 장치 3개 정상 확인(`17_실물실행_스크립트_사용법` §3.1). 첫 1회는 picar 바퀴를 띄워 방향 확인
3. **리허설 1회**(촬영 없이) — 카메라 거리, picar 주행 공간, 각 카메라 화각 확인 → §3·§4 제안값 확정
4. 본 촬영 2~3테이크 — 테이크 사이에 "다시 학습하기"로 처음부터(세션 이어하기 없음)
5. 종료: `bash scripts/rpi/stop_all.sh` → picar 정지 확인 후 배터리 OFF

## 7. 촬영 주의 (알려진 한계)

| 한계 | 영향 | 촬영 대응 |
| --- | --- | --- |
| 소리 없음 | 판정 결과가 소리로 나지 않는다 | 자막·배경음악 |
| BLE 끊김 가능성 | 서보 전류로 micro:bit 연결이 끊길 수 있다 | 끊기면 촬영 중단 → 복구 절차(`16` 안전·복구) 후 해당 테이크 다시 |
| RPi5 발열(쿨러 미장착 시 86°C 기록) | 오래 켜 두면 판정 속도 저하 가능 | 테이크 사이 짧게 쉬기, 쿨러 장착 여부 당일 확인 |
| 서보 반복 부담 | 정격 초과 전압으로 동작 | 테이크 수를 2~3회로 제한(제안) |
