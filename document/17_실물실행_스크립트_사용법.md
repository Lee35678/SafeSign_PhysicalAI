# 실물 실행 스크립트 사용법 (v1.5 — 실물 첫 검증 통과)

**팀명**: 심기일전 · **작성자**: 송승호 (하드웨어·로봇동작 R)
**최초 작성**: 2026-09-28 · **대상**: `scripts/rpi/` — `start_all.sh` · `stop_all.sh` · `status.sh` · `common.sh` · `monitor.py`(자원 기록, §10)

> **이 문서의 범위**: 실물(RPi5 스테이션 + RPi4B picar)을 **명령 하나로 띄우고 끄는 스크립트**의 사용법이다.
> 스크립트는 [루트 README §4.2](../README.md)의 "터미널 4개" 수동 절차를 그대로 자동화한 것이라,
> 수동 명령·최초 설치(§4.1)의 단일 출처는 여전히 README §4다. 네트워크 구축은 [07](07_네트워크설정법.md),
> 시행 당일 역할·안전·육안 기록은 [16 §2.4](16_통합테스트_KPI_CI.md)를 본다.
>
> ✅ **2026-09-29 RPi5+RPi4B 실물에서 §6 첫 실행 체크리스트를 전부 통과했다**(바퀴 띄운 상태 — §9 검증 기록).
> 개발 중 겪은 문제(picar venv 없음·pip 없음)와 조치는 §8 문제 해결에 반영했다.

## 1. 무엇을 해 주나

| 스크립트 | 하는 일 | 장치를 움직이나 |
| --- | --- | --- |
| `start_all.sh` | 사전 점검 → RPi4B picar → RPi5 actuation → vision → web 순서로 기동. 단계마다 `/health`가 정상이어야 다음으로 넘어간다 | 아니오 (서비스만 띄움) |
| `status.sh` | README §4.3 확인 4종 + 두 보드 온도·스로틀링 + tmux 세션 상태 | 아니오 (읽기만) |
| `stop_all.sh` | picar에 **정지·LED 소등 명령을 먼저** 보내고, web → vision → actuation → picar 순서로 Ctrl+C | 정지 명령만 |
| `common.sh` | 위 셋이 쓰는 설정·함수. 직접 실행하지 않는다 | — |

**왜 tmux인가**: 서비스가 보드 안의 tmux 세션에서 돌기 때문에 **SSH가 끊겨도 죽지 않는다.** 수동 방식에서는
SSH가 끊기면 actuation이 죽으면서 BlueZ에 BLE 연결이 남아, 다음 실행 때 micro:bit가 보이지 않았다(README §4.5).

```
PC ──ssh rpi5──▶ RPi5 (192.168.50.1)                      ──ssh──▶ RPi4B (192.168.50.10)
                 tmux 세션 "safesign"                              tmux 세션 "picar"
                   창 0 actuation  :8002 (BLE → micro:bit)          창 0 picar  :8000 (I²C 모터 · GPIO LED)
                   창 1 vision     :8001 (CSI 카메라)
                   창 2 web        :8000 (PICAR_URL=http://192.168.50.10:8000)
```

- picar도 **RPi4B 자체의 tmux**에서 돈다. RPi5 tmux 안에서 SSH로 picar를 띄우면, 그 안쪽 SSH가 끊길 때 picar가 같이 죽고 모터는 마지막 명령 상태로 남는다.
- 각 창은 사람이 터미널에 명령을 친 것과 같다. 서비스가 죽어도 셸이 남아 있어 `↑` `Enter`로 다시 띄울 수 있다.
- (참고) `scripts/rpi/systemd/`에 부팅 시 자동 시작·자동 재시작용 systemd 유닛이 있다(2026-10-03 `d3424dc`, **실물 미검증**). 시연·측정은 이 문서의 tmux 방식으로 한다.
  **둘을 함께 쓰지 않는다** — 포트가 겹치고 micro:bit BLE 연결을 서로 뺏는다. systemd로 켜 둔 보드에서는 `start_all.sh`가 남은 uvicorn으로 멈추므로 안내대로 `sudo systemctl stop ...`을 먼저 한다.

## 2. 최초 1회 준비

README §4.1(가상환경, picamera2, 모델 복사, 펌웨어)이 끝난 상태를 전제로 한다.

| # | 할 일 | 어디서 | 명령 |
| --- | --- | --- | --- |
| 1 | tmux 설치 (인터넷 필요 — 공유기에 연결돼 있을 때) | RPi5 · RPi4B | `sudo apt install -y tmux` |
| 2 | 두 보드 코드를 같은 커밋으로 | RPi5 · RPi4B | `cd ~/git/SafeSign_PhysicalAI && git pull` |
| 3 | (권장) RPi5 → RPi4B 키 로그인 — 비밀번호를 매번 묻지 않게 | RPi5 | `ssh-keygen -t ed25519` (없을 때만) → `ssh-copy-id <rpi4b 계정>@192.168.50.10` |
| 4 | RPi4B 계정이 RPi5와 다르면 접속 대상 지정 | RPi5 | `~/.bashrc`에 `export PICAR_SSH=<rpi4b 계정>@192.168.50.10` |
| 5 | (선택) 마우스 스크롤 기본값 | RPi5 · RPi4B | `echo 'set -g mouse on' >> ~/.tmux.conf` (스크립트가 세션마다 켜 주므로 필수 아님) |
| 6 | 모델 파일 확인 | RPi5 | `ls services/vision/models/` 에 `svm_classifier.joblib`(**git에 없음** — 노트북에서 `scp`), `hand_landmarker.task`(git에 포함 — `git pull`로 받음) |

- 3번을 안 해도 된다. 비밀번호 로그인이면 SSH 연결을 재사용해서 **스크립트 실행 1회에 한 번만** 묻는다(연결은 5분 유지).
- 스크립트는 `bash scripts/rpi/...`로 실행하므로 실행 권한(`chmod +x`)이 없어도 된다.

## 3. 매번 쓰는 법

모두 **RPi5에서**, 저장소 루트(`~/git/SafeSign_PhysicalAI`)에서 실행한다. PC에서는 `ssh rpi5`로 들어간다(07).

### 3.1 켜기

> 📌 **시연·측정 때는 RPi5에 선풍기를 켜 둔다(필수, 장비 챙길 때 선풍기 포함).** 액티브 쿨러는 달지 않고 선풍기로 운용한다(2026-10-03 송승호 결정).
> 선풍기로 10-01 최대 76.3°C, 10-02 KPI 시행 구간 최대 68.6°C, 둘 다 `0x0`였고(§10, 두 번 모두 PLA 케이스 장착 상태), 쿨러·선풍기 없이는 09-25 86.2°C·`0xe0008`이었다(16 §4.6).

```bash
bash scripts/rpi/start_all.sh        # 안전 확인 질문에 y
bash scripts/rpi/start_all.sh -y     # 안전 확인 질문 생략 (같은 세션에서 다시 켤 때)
bash scripts/rpi/start_all.sh -h     # 도움말
```

진행 순서와 각 단계의 통과 조건:

| 단계 | 통과 조건 | 기다리는 최대 시간 |
| --- | --- | --- |
| 0 사전 점검 | §4 표 전부 통과 + 안전 확인 `y` | — |
| 1 picar (RPi4B) | `/health` 응답 + `mock_hardware=false`. `i2c.reachable`이 false면 경고만 | 25초 |
| 2 actuation | `/health` 응답 + `mock_hardware=false`. 기동 때 BLE 스캔(최대 5초)+연결이 끝나야 응답한다. `microbit_connected`가 false면 경고만 | 40초 |
| 3 vision | `/health` 응답 + `camera.state=running` (아니면 중단). 모델 미로드는 경고 | 60초 + 30초 |
| 4 web | `/health` 응답 + `/api/state` 장치 3개 ok (아니면 경고) | 30초 + 15초 |
| 5 요약 | `status.sh` 출력, 브라우저 주소·로그 위치 안내 | — |

끝나면 PC 브라우저에서 안내된 `http://<RPi5 유선 주소>:8000`을 연다.

### 3.2 상태 보기

```bash
bash scripts/rpi/status.sh
watch -n5 bash scripts/rpi/status.sh      # 시연 중 계속 보기 (종료 Ctrl+C — 서비스와 무관)
```

출력 형식 (**값은 예시**다 — 실물 정상 상태라면 `mock=False`, `camera=running`, `i2c=True`, `throttled=0x0`이어야 한다):

```
[서비스]
  ✔ vision     camera=running  fps=26.6  model=True  tau=0.75  N=3
  ✔ actuation  microbit_connected=True  mock=False
  ✔ picar      status=ok  i2c=True  motion=False  stop_error=None  max_speed=50  mock=False
  ✔ web        state=training  progress=1/7  devices={'vision': 'ok', 'actuation': 'ok', 'picar': 'ok'}
[보드]
  ✔ RPi5   temp=62.1'C  throttled=0x0
  ✔ RPi4B  temp=48.3'C throttled=0x0
[tmux]
  ✔ RPi5 'safesign': 0:actuation 1:vision 2:web
  ✔ RPi4B 'picar' 세션 있음
```

### 3.3 로그 보기 (tmux)

```bash
tmux attach -t safesign                   # RPi5 — 창 0 actuation · 1 vision · 2 web
ssh -t <rpi4b 계정>@192.168.50.10 tmux attach -t picar     # RPi4B picar
```

| 하고 싶은 것 | 키 (접두키 `Ctrl+b`) |
| --- | --- |
| 빠져나오기 (서비스는 계속 돈다) | `Ctrl+b` → `d` |
| 창 이동 | `Ctrl+b` → `0` / `1` / `2`, 또는 `n` / `p` |
| 로그 위로 스크롤 | 마우스 휠, 또는 `Ctrl+b` → `[` 후 방향키 (끝낼 때 `q`) |
| 세션 목록 | `tmux ls` |

- ⚠️ attach한 창에서 **Ctrl+C를 누르면 그 서비스가 꺼진다.** 보기만 할 때는 `Ctrl+b d`로 빠져나온다.
- VS Code 터미널로 접속했다면 `Ctrl+b`를 VS Code가 가로챌 수 있다(추정). 그러면 Windows Terminal 등 일반 터미널로 접속한다.

### 3.4 끄기

```bash
bash scripts/rpi/stop_all.sh
```

| 단계 | 하는 일 |
| --- | --- |
| 1 | picar에 정지 + LED 소등 전송. `last_stop_error`가 있거나 `motion_active=true`면 **바퀴를 눈으로 확인**하라고 경고 |
| 2 | web → vision → actuation 순서로 Ctrl+C. 포트가 닫힐 때까지 최대 20초 기다림. web·vision은 필요하면 한 번 더 Ctrl+C, **actuation은 한 번만**(두 번째 Ctrl+C는 강제 종료라 BLE 연결 해제를 건너뛴다) |
| 3 | RPi4B picar에 Ctrl+C. picar는 종료 신호(Ctrl+C·SIGTERM)를 받으면 정지를 쓰고 LED를 끈 뒤 내려간다(2026-10-03 `899f6ba`, **실물 미검증**) — 그래도 1단계의 정지 명령을 먼저 보내는 순서는 그대로 둔다 |
| 4 | 모두 꺼졌으면 두 tmux 세션을 닫음. **안 꺼진 서비스가 있으면 세션을 남겨 둔다**(로그 확인용) |

picar 전원을 끌 때는 안내대로 `ssh <rpi4b> 'sudo shutdown -h now'` → LED가 꺼지면 배터리 스위치 OFF (README §4.5).

### 3.5 비상시

| 상황 | 할 일 |
| --- | --- |
| picar가 안 멈춘다 | **배터리 스위치 OFF가 먼저**다. 스크립트를 기다리지 않는다 (16 §2.4) |
| 서비스는 살아 있고 정지만 보내고 싶다 | `bash -c 'source scripts/rpi/common.sh; picar_stop_command && echo sent'` |
| 한 서비스만 다시 띄우기 | `tmux attach -t safesign` → 해당 창에서 `↑` `Enter` |

## 4. 사전 점검 — 걸렸을 때 조치

`start_all.sh`는 아래 중 하나라도 걸리면 **아무것도 띄우지 않고** 멈춘다(경고 항목은 계속 진행).

| 점검 | 걸렸을 때 메시지 요지 | 조치 |
| --- | --- | --- |
| RPi5 tmux·curl | tmux가 없습니다 | `sudo apt install -y tmux curl` |
| 세션 중복 | 세션 'safesign'이 이미 있습니다 | 이미 켜져 있다 → `status.sh`로 확인, 다시 켜려면 `stop_all.sh` 먼저 |
| 남은 uvicorn (RPi5·RPi4B) | uvicorn이 이미 떠 있습니다 | 수동으로 띄운 서비스를 Ctrl+C로 끈다(`pgrep -af uvicorn`으로 확인). 포트가 겹치고 micro:bit는 BLE 연결을 하나만 받는다 |
| BLE 스캔 | Discovering: yes | 스캔을 켠 창에서 `scan off`, 모르면 `pkill bluetoothctl` (08) |
| 모델 파일 | 분류 모델 없음 / MediaPipe 모델 없음 | `svm_classifier.joblib`은 git에 없어 노트북에서 `scp`로 `services/vision/models/`에 복사. `hand_landmarker.task`는 git에 있으니 `git pull`·`git status`로 확인 |
| 가상환경 | .venv 가 없습니다 | README §4.1 |
| RPi4B SSH | SSH로 붙지 못했습니다 | `ping 192.168.50.10`, 계정이 다르면 `PICAR_SSH=계정@192.168.50.10` |
| RPi4B tmux·세션·uvicorn·venv | (위와 같음) | (위와 같음, RPi4B에서) |
| 안전 확인 | 취소했습니다 | 바퀴 띄움·USB-C 미연결·배터리 스위치 위치를 확인하고 `y` |
| ⚠ `get_throttled`가 `0x0`이 아님 | 경고 | 한 번 선 비트는 재부팅 전까지 남는다. **KPI 측정이면 재부팅 후 다시** (13 §2) |
| ⚠ 두 보드 커밋 다름 | 경고 | 양쪽에서 `git pull` |
| ⚠ RPi5에 커밋 안 된 수정 | 경고 | KPI 기록의 기준 커밋이 불명확해진다 — 커밋하거나 되돌린 뒤 측정 |

## 5. 설정 (환경변수)

모두 선택이다. 기본값으로 README §4의 구성과 같다. 한 번만 바꿀 때는 명령 앞에 붙이고(`PICAR_SSH=pi@192.168.50.10 bash scripts/rpi/start_all.sh`), 계속 쓸 때는 `~/.bashrc`에 `export`한다.

| 변수 | 기본값 | 뜻 |
| --- | --- | --- |
| `PICAR_SSH` | `$PICAR_HOST` | RPi4B 접속 대상. `계정@주소` 또는 `~/.ssh/config` 별칭 |
| `PICAR_HOST` | `192.168.50.10` | RPi4B 주소 |
| `PICAR_URL` | `http://$PICAR_HOST:8000` | web이 부르는 picar 주소 |
| `PICAR_REPO` | `$HOME/git/SafeSign_PhysicalAI` (RPi4B 기준) | RPi4B 저장소 경로 |
| `SAFESIGN_REPO` | 스크립트 위치에서 계산 | RPi5 저장소 경로 |
| `SESSION` / `PICAR_SESSION` | `safesign` / `picar` | tmux 세션 이름 |
| `LOG_ROOT` | `$HOME/safesign_logs` | 창별 로그 폴더 |
| `VISION_URL` · `ACTUATION_URL` · `WEB_URL` | `localhost:8001` · `:8002` · `:8000` | 상태 확인 주소 |

## 6. 첫 실행 체크리스트 (실물 첫 검증)

바퀴를 띄운 상태에서 한다. 결과는 §9 검증 기록에 적는다.

- [ ] `start_all.sh`가 사전 점검을 통과한다 (경고가 있으면 내용 기록)
- [ ] RPi4B에 `picar` 세션이 생기고 picar가 `mock=False`, `i2c=True`로 뜬다
- [ ] RPi5 `safesign` 세션에 창 3개(actuation · vision · web)가 생긴다
- [ ] actuation `microbit_connected=True`, micro:bit LED가 ✓로 바뀐다
- [ ] vision `camera=running`, `fps`가 약 26 (11 §2.1 기준 26.6)
- [ ] web 장치 3개 ok, PC 브라우저에서 SC-01 화면이 뜬다
- [ ] PC의 SSH 창을 강제로 닫았다가 다시 접속해도 `status.sh`가 전부 ✔ (SSH 끊김 내성)
- [ ] `stop_all.sh`가 네 서비스를 모두 끄고 세션을 닫는다
- [ ] 끈 뒤 `bluetoothctl info <micro:bit MAC>`에서 `Connected: no` — **BLE 연결이 남지 않는다**
- [ ] 곧바로 `start_all.sh -y`를 다시 해도 micro:bit가 연결된다
- [ ] 로그 폴더에 `env.txt`와 창별 `.log`가 생긴다

## 7. 로그와 기록

| 파일 | 위치 | 쓰임 |
| --- | --- | --- |
| `env.txt` | RPi5 `~/safesign_logs/<시각>/` | 시작 시각, 두 보드 커밋, 온도·`get_throttled`, 서비스별 `/health` 원문(vision은 모델 번들 메타데이터 포함) → **06 §1-1 테스트 환경**에 옮긴다 |
| `actuation.log` · `vision.log` · `web.log` | 같은 폴더 | tmux 창 출력 전체. 시행 중 이슈는 06 §1-3에 요약 |
| `picar.log` | RPi4B `~/safesign_logs/<시각>/` | picar 창 출력 |

로그 폴더는 저장소 밖이라 git에 섞이지 않는다. 결과 정리에 필요한 부분만 문서에 붙인다. 시행 로그 CSV(web ②-a)는 web이 따로 `services/web/logs/`에 남긴다(스펙 §7).

## 8. 문제 해결

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `$'\r': command not found` | 스크립트가 CRLF로 바뀜(Windows에서 복사) | 저장소의 `.gitattributes`가 `.sh`를 LF로 고정한다. `git pull`로 받거나 `sed -i 's/\r$//' scripts/rpi/*.sh` |

## 10. 자원 모니터 — 테스트 중 메모리·성능 기록 (`monitor.py`)

전체 테스트(⑥ 재시험·KPI 온라인 측정)를 하는 동안 RPi5의 메모리·CPU·온도·판정 fps를 **일정 간격으로 CSV에 남긴다**.
`status.sh`는 한 시점의 상태만 보여 주고 서비스별 메모리·CPU는 보지 않는다. 쿨러 없이 86.2°C·`0xe0008`을 기록한 적이
있고(16 §4.6), 라이브 영상(vision `/stream`)이 교육 화면 내내 JPEG를 인코딩하므로 이 조건에서의 부하를 확인하려는 것이다.

- **읽기만 한다** — vision `/health`, web `/api/state`를 GET으로 읽을 뿐 장치를 움직이지 않는다. 표준 라이브러리만 쓴다(추가 설치 없음).
- 서비스 프로세스는 명령줄의 `--port`로 찾는다(web 8000 · vision 8001 · actuation 8002 — `start_all.sh` 기준). 재기동해도 다시 찾는다.
- 기록 파일: `~/safesign_logs/monitor_<시각>.csv`(창별 로그와 같은 폴더, 저장소 밖).

```bash
# RPi5 — start_all.sh로 기동한 뒤, 별도 SSH 창에서
cd ~/git/SafeSign_PhysicalAI
python3 scripts/rpi/monitor.py                       # 2초 간격, Ctrl+C로 끝내면 요약이 나온다
python3 scripts/rpi/monitor.py --interval 1 --duration 1800   # 1초 간격, 30분 뒤 자동 종료

# 끝난 기록을 다시 요약 (stop_all.sh로 창이 닫혀 요약을 못 봤을 때도)
python3 scripts/rpi/monitor.py --summary ~/safesign_logs/monitor_20260930_140000.csv
```

> ⚠️ `tmux` 세션 `safesign` 안의 창으로 띄우면 `stop_all.sh`가 세션을 닫을 때 요약이 출력되지 않는다(CSV는 행마다 저장되므로 남는다) —
> 별도 SSH 창에서 띄우거나, 나중에 `--summary`로 본다.

**기록 열** (한 행 = 한 시점)

| 묶음 | 열 | 뜻 |
