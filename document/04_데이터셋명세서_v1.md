> 
> 1. 설계 문서에서 “최종 채택 5종”이 정해지면 → 아래 §1 클래스 표 채우기
> 2. §3 촬영 환경/변인을 팀 회의로 정하기 (아래 가이드 참고)
> 3. §4 분할 기준대로 “누가 몇 장씩 찍을지” 담당을 정하기
> 4. 촬영 시작

## 2. 수집 규모

- 클래스당 목표: **약 300장** (랜드마크 기반 파이프라인 채택 시 기준 — 설계 문서 파이프라인 결정에 연동)
- 전체 수집 목표: 6클래스 × 300장 = 1,800장 (초안, 팀 인원/일정에 맞게 조정)

## 3. 수집 프로토콜 (초안 — 확정 필요)

| 항목 | 내용 |
| --- | --- |
| 촬영 기간 | W3 전반 (09.16~09.20, 추석 연휴 전 완료) |
| 촬영 대상 | 팀원 4명 + 외부인 1~2명 (아래 분할 기준 참고) |
| 촬영 환경 | *확정 필요 (조명, 배경, 카메라 거리/각도 범위)* |
| 촬영 변인 | 손 각도, 거리, 좌/우 손 여부 등 — *확정 필요* |

> **촬영 환경/변인은 어떻게 정하나요?**
> 
> - 계획서 제외 범위에 “악조건(역광, 렌즈 이물질, 암실, 야간 조명, 장갑 착용)에서 인식”이 빠져 있으므로, 굳이 극단적 조건까지 찍을 필요는 없습니다. **평범한 실내 조명 + 단순 배경** 정도로 범위를 좁혀도 충분합니다.
> - 변인은 “실제 시연 상황에서 벌어질 수 있는 변화”만 넣으세요. 예: 학습자가 카메라에 너무 가깝게/멀게 손을 댈 수 있으니 거리 2~3단계, 손을 살짝 기울일 수 있으니 각도 ±15도 정도.
> - 변인을 늘릴수록 데이터 품질은 좋아지지만 수집 시간이 늘어납니다. **W3 전반(추석 전) 안에 끝낼 수 있는 범위**로 먼저 정하고, 모자라면 이후 추가 수집하세요.

## 4. 데이터 분할 기준

> ⚠️ 리스크: 팀원 4명만으로 수집 시 과적합 위험 높음 → **인물 단위 분할(subject-wise split)을 강제 적용**.
> 
- Train/Validation: 팀원 4명의 데이터
- Test: **외부인 1~2명** 데이터로 별도 확보 (팀원 데이터와 절대 겹치지 않도록)
- 이유: 같은 사람의 손이 train/test에 섞이면 실제 정답률이 부풀려짐

## 5. 라이선스

| 항목 | 방침 |
| --- | --- |
| 공개 데이터셋 사용 여부 | 산업 안전 수신호 관련 공개 데이터셋은 없는 것으로 확인됨 (거의 확정) → 자체 수집으로 전환 |
| 상업적 사용 제한(NC) 데이터셋 | 파이프라인 검증용으로만 사용, **최종 모델에는 미포함** |
| 자체 수집 데이터 | 팀 내부 동의 하에 수집, 결과보고서/발표자료 공개 범위 사전 협의 필요 |

## 6. 데이터 저장 형식 (초안)

- 원본: 이미지/영상 프레임 + 촬영자 ID(익명화) + 클래스 라벨
- 전처리 후: 랜드마크 21keypoint × (x,y,z) 시퀀스 (JSON 또는 CSV)

> ⚠️ 구체적 파일 포맷·폴더 구조는 팀 확정 필요.
> 
> 
> **정하는 방법:** 데이터를 다루는 팀원(모델 학습 담당)이 “내가 읽기 편한 형식”을 먼저 정하고, 그 형식에 맞춰 촬영 담당이 저장하도록 역할을 나누세요. 예시 폴더 구조를 하나 정해서 이 아래에 실제 경로 예시(`data/raw/{class_name}/{subject_id}_{index}.jpg` 등)로 적어두면 팀원 전체가 헷갈리지 않습니다.
