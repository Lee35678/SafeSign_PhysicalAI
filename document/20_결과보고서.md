## 과제와 접근방법

**과제 배경** — 산업 현장에서 작업자마다 안전 수신호의 이해와 표현이 달라 소통 오류로 인한 사고 위험이 있다.
기존 교육(영상 시청·인쇄물)은 교육자가 학습자의 습득 정도를 객관적으로 판단할 수 없고, 학습자도 자신이
제대로 하고 있는지 알 수 없다.

**핵심 요구** — ① 정답 자세를 **보여줄 것** ② 학습자의 손을 **판정할 것** ③ 결과를 **몸으로 느끼게 돌려줄 것**
④ 교육자가 쓸 수 있는 **정량 지표를 남길 것**.

**선택한 해결방법과 이유** — 로봇 손(AI Hand)이 수신호를 시범하고, 카메라가 학습자의 손을 판정하며,
판정 결과를 주행 로봇(picar)·micro:bit LED·AI Hand로 되먹임하는 **닫힌 제어 루프**로 만들었다.
화면만으로는 "안전 수신호가 실제 장비를 움직인다"는 감각을 줄 수 없다고 보아 물리 장치를 주인공으로 두었다.

인식은 **MediaPipe 손 랜드마크 + SVM**을 택했다. 딥러닝 대비 ① 학습 데이터가 적어도 되고 ② RPi5에서 실시간으로
돌며 ③ 왜 그렇게 판정했는지 설명할 수 있기 때문이다 (05 §3).

## 최종 결과물

**완성 기능** — 회원가입·로그인 → 수신호 7종 시범·판정 → 물리 피드백 → 결과 집계·수료증 발급까지 전 과정.

| 구성 | 내용 |
| --- | --- |
| `services/vision` | 카메라 → 손 랜드마크 21점 → 특징 23차원 → SVM 판정 (τ 0.75 + 3프레임 연속) |
| `services/web` | 교육 진행 상태머신(SC-01~SC-07), 회원·결과 DB(Supabase), 시행 로그 CSV |
| `services/actuation` | AI Hand 7종 제스처 + micro:bit O/X LED (BLE) |
| `services/picar` | 주행·LED 피드백 (별도 보드, Wi-Fi) |
| `services/data` | 학습 데이터 변환·검증 |
| `services/portal` | 회사 소개 웹사이트 (같은 회원 DB) |

**사용 방법** — RPi5에서 `bash scripts/rpi/start_all.sh` 한 줄로 4개 서비스가 기동한다. 학습자는 브라우저에서
가입·로그인 후 "교육 시작"을 누르고, 화면과 AI Hand 시범을 본 뒤 **확인**(화면 버튼·Space·micro:bit A)을 눌러
판정을 시작한다. 7종을 마치면 집계 화면과 수료증이 나온다.

**주요 구성** — 보드 2대(RPi5 고정·RPi4B 주행), 서비스 6개, 수신호 7종, 자동 테스트 92건(web 기준).

**시험 수치**

시도 상한 3회 + 10초 제한(CR-08). 둘 다 09-29 실물 재시험에서 통과를 확인했다.
⚠️ **외부 학습자(현장 작업자) 의견은 아직 받지 못했다** — 평가자 3명이 모두 팀원이다.

# 본문

## 1. 배경 · 사용자 문제

**현행 이슈**

- 산업 현장에서 작업자마다 안전 수신호에 대한 이해와 표현이 달라, 수신호로 의사를 전달할 때 소통 오류가
  안전 사고로 이어질 위험이 있다.
- 기존 교육 방식(교육 영상 시청, 인쇄물)은 **교육자**가 다수 학습자의 습득 정도를 객관적으로 판단하기 어렵고,
  **학습자**도 자신의 이해 수준을 알기 어렵다.

**사용자와 그 문제**

| 사용자 | 문제 |
| --- | --- |
| 신입·현장 작업자 | 수신호를 "봤다"와 "할 수 있다" 사이를 확인할 방법이 없다 |
| 안전 교육자 | 누가 어떤 수신호에 약한지 숫자로 알 수 없다 |

**기대 변화** — 습득 속도·정확도 향상, 소통 오류로 인한 사고 감소, 학습자별 취약 수신호 파악, 정량 지표를 통한
교육 내용 보완.

## 2. 목표와 범위

**목표** — 안전 수신호 7종을 **시범 → 따라 하기 → 판정 → 물리 피드백**의 닫힌 루프로 반복 학습시키고,
교육자가 쓸 수 있는 정량 기록을 남긴다.

**KPI** — F25 요약본의 7개 지표 (01 §목표와 KPI).

**범위에 넣은 것**

- 수신호 7종: 정지 · 서행 · 좌회전 유도 · 우회전 유도 · 확인/완료 · 후진 · 주의
- 손 **정지 자세** 1장면 판정 (연속 동작이 아님)
- 교육 진행 화면 SC-01~SC-07, 회원·결과 DB, 수료증

**범위에서 뺀 것과 이유**

| 뺀 것 | 이유 |
| --- | --- |
| 연속 제스처·동작 추적 | 정지 자세 판정만으로 교육 목적을 달성할 수 있고, 데이터·학습 비용이 크게 늘어난다 |
| 수신호 등록·관리자 화면 | 교육용 고정 커리큘럼 7종이면 충분 (03 §6) |

| CR-06 | 09-18 | 학습 중간 이탈 후 **이어하기 구현하지 않음** | 교육 1회가 짧고 세션 복구 복잡도가 이득보다 크다 | SC-07은 "처음부터 다시" 안내만 | 범위 축소, 핵심 흐름에 집중 |

## 4. 최종 결과물

(F25 요약본 "최종 결과물" 참조 — 아래는 보완 설명)

**판정 파이프라인**

```
카메라 → MediaPipe 손 랜드마크 21점 → 좌우손 통일·정규화 → 특징 23차원(관절 각도·거리)
      → SVM(RBF) → 확률 → τ(0.75) + 소속 게이트 + 3프레임 연속 → 판정 확정
```

**물리 피드백** — 판정 확정 시 picar(주행·LED) → micro:bit(O/X LED) → AI Hand(정답 자세 또는 재시범) 순으로
전송한다. 순서는 반응 시작을 앞당기기 위해 09-28에 바꿨다.

**기록** — 회원 DB에 회차별·수신호별 결과가 쌓이고, KPI용 시행 로그는 CSV로 따로 남는다.

## 6. 사용자 의견

> 【확인 필요】 **외부 학습자(현장 작업자) 대상 의견 수집은 아직 하지 못했다.** 평가에 참여한 3명은 팀원이다.
> 아래는 실사용 시험 중 **관찰된 사용성 문제**로, 전부 수정에 반영됐다.

| 관찰된 문제 | 반영 |
| --- | --- |
| "AI Hand를 보기도 전에 오답이 떴다" | 확인 버튼 도입 (CR-07) |
| "틀리기만 하면 다음으로 안 넘어간다" | 시도 상한 3회 + 10초 제한 (CR-08) |
| "손을 잠깐 내렸는데 카메라 실패 화면으로 넘어간다" | 시범 단계에서는 미검출을 세지 않도록 수정 |
| "카메라 실패 화면에서 재시도를 눌러도 안 돌아간다" | 재시도 → 시범 단계 + AI Hand 재시범으로 재작성 |
| "좌회전인지 후진인지 로봇 손만 봐서는 모르겠다" | AI Hand 교체로 해결 |

**W5에 할 수 있는 보완** — 시연·발표 자리에서 참관자 3~5명에게 5분 체험 후 ① 무엇을 하라는지 알았는가
② 틀렸을 때 왜 틀렸는지 알았는가 ③ 다시 하고 싶었는가 3문항만 받아도 "사용자 의견" 항목을 채울 수 있다.

## 7. 달성 · 부분 · 미달 판정

**종합 판정: 부분 달성**

| 구분 | 내용 |
| --- | --- |
| **달성** | 판정 성능 5개 지표(KPI-1~5) 전부 목표 충족. 특히 오분류율 0%와 치명 오분류 0건은 안전 교육 목적상 가장 중요한 지표다 |
| **부분** | 전 구간 통합 동작은 실물에서 확인했으나, 지연 2개 지표(KPI-6·7)는 **아직 측정하지 않았다** |
| **미달** | 현재 시점에 목표 미달로 확정된 지표는 없다. 다만 KPI-7은 "완료" 기준을 채택할 경우 구조상 달성 불가(약 3.0초 대 목표 2.0초) |

> **"달성"이라고 쓰지 않은 이유** — 7개 중 2개를 재지 않았는데 전체를 달성이라고 적으면 근거가 없다.
> 근거 있는 "부분 달성"으로 적고, 10-03~04 측정 후 완성본에서 갱신한다.
