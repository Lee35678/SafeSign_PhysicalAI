## 안건 1. 조종 모드를 넣을지 (8분)

**결정권자**: 이동혁(요구사항·범위 A, 하드웨어·로봇동작 A) · 의견 송승호·김지훈(요구사항·범위 R)

### 문제

교육 모드는 **정답일 때만** picar가 정해진 동작을 2초 합니다. 조종 모드는 판정을 **계속** 주행으로 바꿉니다.
실제 유도 신호와 의미가 맞고 시연 효과가 크지만, 오분류가 곧바로 주행이 되고 범위 밖 기능입니다.

| 장점 | 위험 |
|---|---|
| 실제 유도 신호 의미와 일치 — 신호를 주는 동안 움직이고, 멈추면 멈춘다 | ① **오분류가 곧 오주행** (교육 모드는 정답일 때만 2초) |
| 통신 두절·브리지 다운·손 사라짐이 **모두 자동 정지**로 끝난다 (fail-safe) | ② 소프트웨어 워치독이라 **picar 프로세스 `kill -9`·멈춤 시 MCU가 마지막 명령을 유지 → 폭주**. 08 "picar 비정상 종료" 행 **미착수**. 최종 수단은 배터리 스위치 |
| 명령 하나가 유실돼도 다음 명령(약 0.1초 뒤)이 이어받는다 | ③ 손을 내린 뒤에도 **최대 약 0.7초 더 주행** (워치독 창 0.5초 + 판정·폴링 지연) |
| 학습자가 직접 조종하는 인터랙티브 시연 | ④ **I²C 부하 증가** — `speed 50` 정지 실패 이력(13 §4.1 #10, 조치 후 #11 통과), 주행 I²C 유실 1.4%(13 §5 #7, 검토 중) |
| | ⑤ 00 사용자시나리오·10_PRD에 없는 기능 → **범위 변경, 문서 갱신 비용** |
| | ⑥ KPI 7개 밖 기능이라 **지표로 제시할 수 없다** — 시연용 |

확인할 것:
- 01 §범위 제외 항목 "연속 제스처·동작 추적 (하드웨어 제약)"과 겹쳐 보일 수 있습니다. 조종 모드는 **정적 수신호 판정을 반복**할 뿐 동작 추적은 아니지만, 해석은 요구사항 A(이동혁)의 확인이 필요합니다.
- 일정: 약 3일 작업이 송승호의 W4 다른 일과 겹칩니다. 특히 **RPi5 액티브 쿨러 장착**(08 열 스로틀링 행 "대응 중(쿨러 미장착)")은 KPI 최종 시행의 선행 조건이므로, 조종 모드 작업이 이것을 밀어내지 않는 것을 전제로 제안합니다.

### 선택지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | **선택 데모 모드(기본 off)** — 교육 흐름과 분리, 브리지 스크립트로만 켠다 | web·KPI 경로 무변경. 작업이 송승호 영역에서 끝남. 접어도 교육 흐름에 영향 없음 | 위 위험 ①~⑥ 관리 필요 |
| B | 안 넣음 — 결과보고서에 "향후 과제"로만 | 비용 0, 일정 위험 0 | 시연 효과·fail-safe 설계 사례를 못 보여줌 |
| C | web 교육 흐름에 통합 | 화면·시나리오 안에서 자연스럽게 보임 | web 상태머신·KPI 경로 변경 → 조은수·이동혁 작업 증가(14 §8). web ①-a·②-a가 아직 미구현이라 **KPI 일정 위험** |

**추천: A안.**
**잠정치: A안으로 진행하되, 안건 2 게이트를 통과할 때만 시연·보고에 넣는다** (미통과 시 B안으로 전환).

반영할 문서(A안 채택 시): 10_PRD 범위, 01 §범위(01은 "변경이 잦지 않아야 하는" 문서라 버전 인상 필요 여부 함께 확인), 00은 PDF 원본이라 수정 대신 10에 "시나리오 외 데모"로 명시할지 확인, 08 신규 리스크 행, 11 §10·13 §5(실측)

## 안건 2. go/no-go 게이트 (5분)

**결정권자**: 게이트 기준 승인 이동혁(하드웨어·로봇동작 A) · 판정 송승호(R, 제안) · 시연영상 편입 여부는 전원(보고·최종 제출)

### 문제

시연영상 촬영은 W5(10-05 ~ 10-07), 제출은 10-08입니다. 조종 모드를 늦게 접으면 시연 콘티·보고서 구성이 촬영 직전에 흔들립니다.
그래서 **접을 날짜와 기준을 미리** 정해 둡니다.

게이트 기준(제안 — 각 기준에 대응하는 시험·필수 여부는 [구현 계획 §5.4](picar_워치독_조종모드_구현계획.md) 확정안):

| # | 항목 | 통과 조건(제안) |
|---|---|---|
| 1 | 손을 내림 → 정지 | 반복 시행 전부 약 0.7초 안에 정지 |
| 2 | 장애 주입 — 브리지 종료 | picar가 워치독 창 안에 스스로 정지 |
| 3 | 장애 주입 — Wi-Fi 끊김(RPi5 AP ↔ RPi4B) | 동일 |
| 4 | 장애 주입 — vision 중지·손 사라짐 | 동일 |
| 5 | 장애 주입 — picar 프로세스 `kill -9` | **멈추지 않는 것이 예상 결과** → 배터리 스위치로 끊는 절차를 리허설로 확인 |
| 6 | I²C | 정지 실패 0회(`/health` `last_stop_error`), 주행 I²C 실패율 기록 |
| 7 | 교육 모드 회귀 | 조종 모드 off에서 기존 2초 자동 정지 동작 유지, `services/picar/tests` 통과 |

### 선택지

| 안 | 내용 | 결과 |
|---|---|---|
| **A** | **10-02(금)까지 실물 검증(장애 주입 포함) 통과 못 하면 접고 "향후 과제"로** | W4 안에 결론, 촬영(W5) 전 콘티 확정 가능 |
| B | 게이트 없이 W5까지 진행 | 촬영 직전까지 불확실 |
| C | 10-04(일, W4 마감) 게이트 | 여유 2일 더, 대신 콘티 확정이 W5 첫날로 밀림 |

> 약 3일 작업이라 10-02에 맞추려면 **늦어도 09-29(화) ~ 09-30(수)에 착수**해야 합니다.
> 회의가 그보다 늦게 열리면 게이트 날짜를 같이 조정해야 합니다.

**추천: A안. 게이트 결과로 시연영상 촬영(W5) 포함 여부를 정한다.**
**잠정치: 10-02(금) 게이트, 판정 송승호.** 결과는 게이트 직후 정기 회의에서 공유하고 촬영 포함 여부를 다시 논의.

## 안건 3. 시연 안전 규칙 (7분)

**결정권자**: 이동혁(하드웨어·로봇동작 A) · 작성 송승호(R)

### 문제

조종 모드는 판정이 곧 주행이고, 소프트웨어 워치독이 못 막는 경우(프로세스 kill·멈춤)가 있습니다.
시연 규칙을 사람 쪽에 미리 정해 둬야 합니다.

| 규칙 | 제안 | 근거 |
|---|---|---|
| 속도 상한 | **조종 모드 20 ~ 30**, 첫 실물은 20에서 시작 | 교육 모드는 서행 20·좌우회전/후진 40, 서비스 상한 `PICAR_MAX_SPEED` 50(13 §4.5). 50에서 정지 실패 관측 이력(13 §4.1 #10). 오분류가 곧 오주행이고 손 내린 뒤 약 0.7초 더 달린다 |
| 배터리 스위치 담당자 | **조종자(수신호를 주는 사람)가 아닌 1명**을 지정, 스위치에 손이 닿는 위치 | 프로세스 kill·멈춤 시 유일한 정지 수단(08 "picar 비정상 종료" 행, 13 §5 #4). 담당자 이름은 **확인 필요** |
| 두 모드 동시 실행 금지 | 브리지와 web 교육 흐름을 **동시에 띄우지 않는다**. 전환 절차: 브리지 종료 → picar 정지·`/health` `motion_active=False` 확인 → web 시작 | 두 송신자(`/picar`·`/drive`)가 섞이면 의도하지 않은 주행. 구현 계획은 엔드포인트를 분리해 모드 전환에 picar 재시작이 필요 없음(구현 계획 §1) |
| 주행 구역 | 바닥에 표시한 구역 안에서만, 진행 방향에 사람·장비·책상 끝이 없게 | 오주행 + 추가 주행 거리 여유. 구역 크기는 시연 장소에 맞춰 **확인 필요** |

시연 중 서비스 강제 종료 금지는 08 기존 대응과 같으므로 그대로 따릅니다.

**추천: 위 4개 규칙 모두 채택, 속도 상한 30.**
**잠정치: 속도 상한 20, 나머지 3개 규칙은 제안대로.** 배터리 스위치 담당자는 다음 회의에서 지정(그전 실물 검증은 송승호 본인 담당 영역이므로 송승호가 겸함).

반영할 문서: 구현 계획 문서, 17 실물실행 스크립트 사용법(브리지 기동·전환 절차), 08 비정상 종료 행 대응 칸

## 사전공유 4. (결정 불필요 / 2분) 발표·보고 표현

- 조종 모드는 **KPI 7개 밖의 시연 기능**으로 명시합니다. 06 2부와 KPI 표에는 넣지 않고, 게이트 실측(손 내림 → 정지 시간 등)은 참고치로만 씁니다.
- 결과보고서 위치(제안): 게이트 통과 시 "추가 시연 기능(KPI 외)" 짧은 절 + fail-safe 설계 설명, 미통과 시 "향후 과제" 한 단락.
- 발표(10-12)에서는 송승호 개인 역할 설명 부분에서 fail-safe 설계 사례로 다룰 수 있습니다(제안).
- KPI 측정방법 안건 3(물리 피드백 "시작"/"완료")에는 영향이 없습니다 — 조종 모드는 KPI 측정 경로를 쓰지 않습니다.

담당 제안: 결과보고서 반영은 보고서 작성 담당과 **확인 필요**
