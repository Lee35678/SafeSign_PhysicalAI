# web 시연 화면 연결 방식 결정 (RPi5 ↔ PC)

**팀명**: 심기일전 · **작성일**: 2026-09-21 · **작성자**: 송승호

---

## 1. 배경

`services/web`(교육 상태머신 + 프론트엔드)는 RPi5에서 동작하며, vision(`GET /latest`)·actuation(`POST /command`)은
RPi5 로컬에서, picar(`POST /picar`)는 RPi4B 8GB와 **Wi-Fi**로 통신한다(03_인터페이스계약서_v2 §5-2,
시스템_구성도_초안 v3). 시연 시 web 화면을 여러 명이 동시에 볼 수 있도록 **별도 PC를 web 백엔드에
연결하는 방안**을 검토했다.

이때 "RPi5 ↔ RPi4B(picar) Wi-Fi 통신"과 "RPi5 ↔ PC(web 시연 화면) 연결"이 동시에 이루어져도 괜찮은지가
쟁점이었다. picar 쪽은 이미 500ms 타임아웃 + 1회 재시도, P95 ≤ 2.0초 KPI가 걸려 있는 통신이라(
03_인터페이스계약서_v2 §5-2·§5-4), 여기에 부담을 주지 않는 연결 방식을 골라야 했다.

## 2. 검토한 대안 비교

| 항목 | 로컬 (RPi5 직결 모니터) | PC 연결 — Wi-Fi | PC 연결 — UTP 직결 |
| --- | --- | --- | --- |
| **성능** | web↔vision/actuation 전부 localhost, 지연 거의 0 | RPi5 Wi-Fi 라디오가 picar(outbound)와 PC(inbound)를 겸용 → AP 혼잡 시 jitter로 picar 500ms 예산 잠식 가능 | PC↔RPi5가 완전히 별도 물리 링크(유선) → picar Wi-Fi 통신과 자원을 전혀 공유하지 않음. 기가비트 유선이라 지연도 Wi-Fi보다 낮고 안정적 |
| **기간 내 시현 가능성** (제출 10/08, 발표 10/12) | 이미 구현된 구조 그대로 사용, 추가 개발 거의 불필요 | 공유기 품질/CORS/방화벽 등 확인 변수 추가 → 일정 부담 | 케이블 + 고정 IP(또는 link-local 자동할당)만 설정하면 됨, 확인 항목 적음. 발표장 공용 Wi-Fi 품질(통제 불가 변수)에 의존하지 않음 |
| **장점** | 세팅 단순 | 다수 관람 가능, RPi5 옆에 안 붙어도 됨 | 다수 관람 가능하면서 picar의 500ms 예산과 완전히 분리됨 |
| **단점** | 관람객이 RPi5 앞에 몰려야 함 | 네트워크 변수 이중화, 지연 원인(picar vs PC) 구분 어려움 | PC가 케이블 길이만큼만 RPi5 근처에 있어야 함(이동 제약, 다만 RPi5·PC 모두 고정 스테이션이라 실질 제약은 적음). RPi5/PC 각각 여유 이더넷 포트 확인 필요(노트북이면 USB-Ethernet 어댑터 필요할 수 있음) |
| **리스크 발생 가능성** | 낮음 (기존 picar Wi-Fi 리스크뿐) | 중간~높음 (picar 리스크 + 신규 AP 경합 리스크 중첩) | 낮음 (유일 리스크는 케이블 탈락/밟힘 등 물리적 사고) |

## 3. 결정

**RPi5 ↔ PC는 UTP(이더넷) 직결로 연결한다.**

- picar와의 Wi-Fi 통신(500ms 타임아웃 + 1회 재시도, P95 ≤ 2.0초 KPI)과 자원을 공유하지 않아, 기존에
  이미 걸려 있는 picar Wi-Fi 지연/끊김 리스크(08_리스크레지스터 §33)를 악화시키지 않는다.
- 라우터 없는 1:1 직결이므로 IP 구성이 단순하다 — 고정 IP 수동 설정(예: RPi5=192.168.10.1,
  PC=192.168.10.2) 또는 link-local 자동할당(169.254.x.x)에 맡겨도 된다. mDNS/공유기 품질 문제로
  고민할 필요가 없다.
- 발표장 공용 Wi-Fi 환경(다른 팀 기기 간섭 등 통제 밖 변수)에 의존하지 않아 D-17(제출)/D-21(발표)
  일정 내 안정적으로 검증 가능하다.

## 4. 남은 확인 사항

- [ ] RPi5·PC 각각 여유 이더넷 포트 확인 (노트북이면 USB-Ethernet 어댑터 필요 여부)
- [ ] IP 할당 방식 확정: 고정 IP 수동 설정 vs link-local 자동할당
- [ ] `services/web`의 `PICAR_URL`·web 접속 주소 등 환경변수(`.env`)에 RPi5↔RPi4B(Wi-Fi), RPi5↔PC(UTP)
  두 링크의 IP를 분리 기재
- [ ] 시연 현장 케이블 길이/배치(관람객 동선과 케이블이 겹치지 않도록) 사전 확인
