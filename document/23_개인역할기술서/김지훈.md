## 3. 분석 · 선택 · 구현 · 시험 · 협업 행동

### 3-1. 분석

- **공개 데이터의 검출률을 먼저 쟀다(09-20)** — 원본이 많아도 MediaPipe가 손을 못 찾으면 학습에 쓸 수 없다. `--probe`로 클래스별 검출률을 먼저 확인하는 절차를 만들었다. 전수 변환 결과 클래스별 검출률은 79.1~100.0%였다([04 §2-2](../04_데이터셋명세서.md)).
- **negative 후보가 쓸 수 없다는 것을 실측으로 확인(09-20)** — asl-alphabet의 `nothing` 폴더는 손이 없는 배경 사진이라 랜드마크가 0건(검출률 0.0%)이었다. "손 없음"은 분류기 이전 단계(`hand_detected=false`)에서 걸러진다는 점도 함께 정리해, 선택지 두 개(7클래스 + τ 미판정 / 직접 촬영)로 안건을 만들었다([services/data/README.md](../../services/data/README.md) "아직 확정 안 된 것").
- **확보 직후 남은 문제를 숫자로 남겼다** — 클래스 불균형 최대 18배(정지 308장 대 좌회전_유도 5,629장)와 정지 치명 오분류를 README·커밋에 미해결로 적었다(`bf51609`, [04 §2-3](../04_데이터셋명세서.md)).
- **DB 저장 항목의 빈틈을 찾음(09-30)** — 18 §3은 불합격을 두 사유로 정의하는데 저장은 `given_up` 불리언 하나뿐이었다. 학습자가 무엇을 한 것으로 읽혔는지도 저장되지 않았다(`1fc35c5` 커밋 메시지).

## 5. 문제 해결 과정과 다음에 개선할 점

### 5-1. 문제 해결 사례

**① 한글 경로에서 MediaPipe가 파일을 못 엶(09-20)**
- 문제: Windows 사용자명이 한글인 경로에서 변환이 실패했다.
- 원인: MediaPipe 네이티브 코드와 `cv2.imread`/`cv2.imwrite`가 한글 경로를 열지 못한다.
- 조치: 모델 파일을 직접 읽어 `model_asset_buffer`로 넘기고, 이미지는 `np.fromfile` + `cv2.imdecode`로 읽었다.
- 결과: 전수 변환을 마쳤고, "다른 서비스에서 같은 증상이 나오면 같은 방법으로"를 README 함정 절에 남겼다([services/data/README.md](../../services/data/README.md)).

**② 데이터가 없는 손모양 — 바꿨고, 대가가 따랐다(09-20)**
- 문제: 확인/완료 "따봉"은 공개 데이터에 대응 클래스가 없었고, 우회전 유도 "엄지+약지"는 사람이 재현하기 어려웠다.
- 조치: 주먹, 엄지+소지로 바꾸는 안을 내 팀 승인을 받았다. 02·03·04·10 등 갱신할 문서 목록도 README에 남겼다.
- 결과: 7종 모두 데이터를 확보했다. 대신 엄지 하나 차이인 주의↔우회전 유도가 전체 오분류의 41%를 차지하는 가장 큰 혼동 쌍이 됐다. vision 담당이 손모양 재설계 대신 특징을 `joint23`으로 바꿔 대응했다(12 §3-1·§3-3, 02 §4 참고사항 6).

**③ 변환 직후 정답률이 부풀려져 있었다(09-20 → 09-21)**
- 문제: 변환 직후 README에 5겹 교차검증 정답률 97.7%(2,708건 표본)를 적었다.
- 원인: 공개 데이터에 복사본·연속 촬영 컷이 섞여 있었다(전체 97.7%가 805개 세션, 표본 69.8%에 유사도 0.999 이상 쌍둥이). 같은 세션이 학습·시험에 함께 들어가면 점수가 부풀려진다. 이 누수는 vision 담당(이동혁)이 찾았다.
- 조치(이동혁): 기본 분할을 세션 단위 GroupKFold로 고정했고, 무작위 분할 점수는 보고에 쓰지 않기로 했다. 04의 97.7% 표기는 v2.1에서 "오기"로 정정됐다.
- 결과: 무작위 5겹 98.81%가 세션 단위에서는 77.57%였다(12 §3-2). 공개 데이터 점수는 KPI 근거에서 빠졌다(04 §4, 08).

**④ `last_predicted` 정의와 코드 불일치(09-30 발견 → 10-04 수정)**
- 문제: 18 §2-3은 "미검출이면 빈 값"인데, 시간 초과로 끝나면 출력 전용 라벨 `negative`가 DB에 남을 수 있었다. 09-30 연동 확인 때 "남은 불일치"로 기록됐고(15 09-29~30 항목), 10-02 검토에서 08 신규 행이 돼 김지훈이 수정 담당이 됐다.
- 원인: 시간 초과 경로에서 마지막 프레임의 vision 추정을 그대로 저장했다.
- 조치: `None`·`negative`는 빈 값으로 저장하고, τ 미달 시간 초과는 목표 수신호 이름을 남기도록 뜻을 18에 적었다. 회귀 테스트 2건은 고치기 전 코드에서 실패하는 것을 확인했다.
- 결과: 08 행 해결, 18 v1.6·19 v1.4에 반영. web 테스트 126건 통과(`f13d24a`).

**⑤ 만든 기능이 다음 날 회의로 바뀜(09-28 → 09-29)**
- 문제: 09-28 완료한 ⑨ CSV 내려받기와 ⑩ 예시 사진이 09-29 회의에서 각각 회원 DB 자동 저장과 라이브 영상 + 손가락 패턴으로 바뀌었다.
- 조치: 바뀐 저장 방식에 맞춰, 불합격 사유와 인식된 수신호를 DB에 남기는 필드를 추가했다(09-30 `1fc35c5`).
- 결과: CSV는 회원 DB와 회사 사이트 조회로 대체됐다. 사진 파일은 `2c19d9c`에서 삭제됐지만 git 기록에 남아 mock 화면 캡처에 쓰였다(14 부록 A). 【본인 확인: 이 경험에서 느낀 점】
