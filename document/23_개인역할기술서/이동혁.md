- **회원·결과 저장과 회사 사이트** — Supabase 회원·수신호별 합격/불합격 저장([18](../18_DB설계서.md)), 회사 웹사이트([19](../19_회사웹사이트.md)), 교육장·회사 사이트 화면 디자인을 만들었다. 모두 KPI 밖 부가 기능이다([01 §범위](../01_프로젝트계획서.md)).

## 3. 분석 · 선택 · 구현 · 시험 · 협업 행동

### 3-1. 분석 — 숫자를 의심하고, 감 대신 계산으로

- **클래스 설계 검증(09-17~18)** — 설계 문서에서 "서행"과 "후진"이 같은 손 모양(검지+중지)인 것을 데이터 수집 전에 찾았다. 모델로는 50%가 한계인 구조라 후진을 "검지만 펴기"로 재설계했다(12 §1-1).
- **98.81%를 의심(09-20~21)** — 첫 학습 결과가 너무 좋아 파일명을 조사했다. 복사본과 연속 촬영 세션이 섞여 같은 사진으로 학습·시험하고 있었다. 세션 단위로 나누니 77.57%였다(12 §3-2).
- **손 모양 32가지 전수 계산(09-20~21)** — "우회전 유도만 다른 손 모양으로 바꾸면 되지 않나"를 감이 아니라 계산으로 확인했다. 1개 교체는 어떤 후보든 최악 쌍이 0.9739로 개선이 없었다(12 §3-4).
- **τ가 못 막는 것 측정(09-22)** — 한 클래스를 학습에서 빼고 "모르는 자세"로 넣는 open-set 측정에서 77.3%가 confidence 0.90 이상으로 오판됐다. 분리 능력(AUC)은 클래스 중심 거리 0.932, confidence 0.594였다(12 §5-1).
- **공개 88.7% 대 자체 97.1%의 원인 분석(09-22)** — 자체 촬영이 학습에 섞였는지(아님, 학습 건수 27,735 = 공개 데이터 수), 집계 단위 효과(1.5%p뿐), 데이터 난이도를 차례로 확인했다(12 §8-3).

### 3-2. 선택 — 주요 결정과 근거

| 결정 | 버린 대안 | 근거 |
| --- | --- | --- |
| 랜드마크 + SVM(RBF) + Platt 확률 보정 | 이미지 분류(CNN), MLP·랜덤포레스트 | 데이터량·RPi5 CPU 실시간·판정 근거 설명 가능성([05 §5](../05_모델카드.md), [02 §2](../02_설계문서.md)). 단 05 §5-2는 이 근거가 **설계 당시의 정성 판단**이고 같은 조건의 MLP·RF 정량 비교는 하지 않았다고 적는다 |
| 관절 특징 23차원(`joint23`) | 좌표 63차원, 좌표+관절 86차원, 계층 분류, NCA 거리 학습 | 논문 검토 자료의 전략 5개를 공개 데이터 세션 분할로 직접 측정했다. 23차원 88.71%(기준 63차원 77.57%), 86차원 82.99% — 원좌표가 잡음이라 더하지 않고 **대체**했다(12 §6). 현재 기본 조건 값은 88.68%([05 §3-5](../05_모델카드.md)) |
| 세션 단위 GroupKFold로 고정 | 무작위 5겹 | 무작위 98.81%는 허수였다(12 §3-2) |
| 소속 게이트(클래스별 임계, p10) 추가 | τ 값 조정만 | τ는 "7종에 속하나"를 재지 못한다(12 §5). p10에서 미지 자세 차단 75.0% / 정상 오거부 2.9%(12 §8-1). 05 v3.7은 p10을 **잠정**(촬영자 1명 기준)으로 적는다 |
| 7클래스만 학습, 손 방향 축 도입 | negative 8번째 클래스, 손 모양 재설계 | 이동혁이 선택지·근거 수치·권고를 붙인 회의 자료를 만들고 09-21 회의에서 결정했다(12 §4, [archive/회의안건_2026-09-21](../archive/회의안건_2026-09-21.md)) |

## 5. 문제 해결 과정과 다음에 개선할 점

### 5-1. 문제 해결 사례

**① 정답률 98.81%가 허수였다(09-20~21)**
- 문제: 첫 학습 결과가 98.81%로 지나치게 높았다.
- 원인: 공개 데이터에 복사본과 연속 촬영 컷이 섞여 있었다(97.7%가 805개 세션, 69.8%가 유사도 0.999 이상 쌍). 무작위로 나누면 같은 사진으로 학습하고 시험하는 셈이었다.
- 조치: 파일명에서 세션 키를 만들어 학습 스크립트 기본 분할을 세션 단위 GroupKFold로 고정했다. 무작위 분할 점수는 보고에 쓰지 않기로 했다.
- 결과: 실제 실력 77.57%(−21.2%p)를 기준으로 특징 개선을 진행해 88.68%까지 올렸다(12 §3-2·§6).

**② 웹캠 정답률 28.2% — 모델이 아니라 측정 도구가 틀렸다(09-22)**
- 문제: 특징을 바꾼 뒤 "오판정이 더 심해졌다"는 보고가 왔고, 진단 로그 4,800프레임의 정답률이 28.2%였다.
- 원인: 이동혁이 만든 `webcam_check.py` 라벨링 방식이 숫자키를 누른 뒤 다음 키까지 수백 프레임을 같은 라벨로 기록해 전환 프레임이 섞였다. 이 과정에서 "소지가 안 펴진다"는 오진도 했다.
- 조치: 이전 모델로 같은 프레임을 재판정(26.0%)해 특징 교체가 원인이 아님을 먼저 확인했다. 이어 `record_dataset.py`(카운트다운 후 3프레임)로 다시 찍었다.
- 결과: 105프레임 전부 정답, 최저 confidence 0.866. 오진도 보고서에 그대로 남겼다(12 §7).

**③ "엄지만 폈는데 우회전 유도" — τ로는 못 막는 입력(09-22)**
- 문제: 7종이 아닌 손 모양이 높은 확신으로 7종 중 하나로 판정됐다.
- 원인: 분류기 확률은 7종 안에서 합이 1이라, 낯선 입력도 가장 비슷한 클래스가 높은 값을 받는다. open-set 측정에서 77.3%가 confidence 0.90 이상으로 오판됐다.
- 조치: 판정 뒤 "그 클래스에 속하기는 하는가"를 보는 소속 게이트(클래스 중심 코사인, 클래스별 임계)를 넣고, 같은 사람·같은 카메라 데이터로 동작점을 p10으로 정했다.
- 결과: 미지 자세 차단 75.0%, 정상 오거부 2.9%(12 §5·§8-1). 단 7종 아닌 자세의 19%는 여전히 샌다(12 §9-2).

**④ 외부인 ext03 61.4% — 고치지 않고 버렸다(09-29)**
- 문제: 외부인 70시도를 넣으니 정답 61.4%·오분류 21.4%였다.
- 원인: 20테이크가 정의와 다른 손 모양이었고(좌회전 유도를 V자로 등), 기울인 우회전 유도 5/6이 주의로 가는 실제 약점도 있었다.
- 조치: 20테이크만 빼면 결과를 본 뒤의 선별이 된다. 팀 결정으로 ext03 전체를 폐기하고 팀원 3명이 RPi5 CSI로 210시도를 다시 찍었다. 같은 ID 덮어쓰기 문제도 함께 막았다.
- 결과: 210시도로 5개 지표 달성(06 §2-1). 기울인 우회전 유도 약점은 재현되지 않았고, 대신 후진·확인_완료의 우기울임 과차단이 새 약점으로 나왔다(12 §13-3·§13-8).

**⑤ 일치율 — 두 번 고쳤다(09-30)**
- 문제: 정답인데 일치율 55~69%, 일부러 다른 수신호를 보여 줘도 85%가 떴다.
- 1차 원인과 실수: 환산 구간이 7종 공통이었다. 클래스별 구간으로 고쳤지만 코드를 바꾼 뒤 vision을 재시작하지 않고 "반영됐다"고 말해, 다음 시험이 옛 계산으로 나갔다.
- 2차 원인: 목표가 아니라 예측된(틀린) 수신호와 비교했고, 코사인 유사도 자체가 7종을 가르지 못했다(주의 ↔ 우회전 유도 대표 손끼리 0.958).
- 결과: 일치율을 목표 수신호 확률 × 100으로 바꿨다. 다른 수신호를 한 손은 중앙값 0~1점이 됐고, 화면 75점 = 판정 기준 τ 0.75로 맞춰졌다(12 §13-7, 05 §10-8).
