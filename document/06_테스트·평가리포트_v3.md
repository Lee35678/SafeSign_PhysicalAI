# 1부 — 테스트 기록

목적: 각 테스트 시행의 원본 로그를 남겨 2부(혼동행렬·지연분포)의 근거 데이터로 사용.

> **이 부분 작성법**
>
> - 사람이 손으로 표를 채우는 것이 아니라, **시스템이 자동으로 로그를 남기도록 코드를 짜서** 그 결과를 CSV로 뽑은 뒤 이 문서(또는 첨부 CSV)에 붙이는 것을 권장합니다. 시도 횟수가 많으면(수십~수백 건) 표를 수작업으로 채우기 어렵습니다.
> - 최소한 "정답 클래스"(테스트할 때 미리 정해서 학습자에게 지시한 수신호)와 "예측 클래스"(시스템이 실제로 판정한 결과)는 반드시 구분해서 기록하세요 — 이 둘을 비교한 것이 정답률·혼동행렬의 기초 데이터입니다.
> - "비고" 칸에는 특이사항(예: "학습자가 손을 화면 밖으로 벗어남", "조명 어두워짐")을 남겨서 나중에 2부에서 오류 원인을 분석할 때 참고하세요.

# 2부 — 평가 리포트

1부의 "숫자 로그"를 "그림/표로 정리해서 결론을 내리는" 부분입니다. 순서:

1. 1부의 CSV(또는 표)를 파이썬(pandas 등)이나 스프레드시트로 불러온다.
2. §2-1 요약표부터 채운다 — 단순 집계(평균, 비율)로 계산 가능.
3. §2-2, §2-3처럼 그림이 필요한 항목은 아래 가이드대로 만든다.
4. §2-4, §2-5는 숫자를 보고 팀이 해석/논의한 결과를 문장으로 적는다.

## 2-1. 요약

| 지표 | 목표값 | 실측값 | 달성 여부 |
| --- | --- | --- | --- |
| 정답률 | ≥ 92% |  |  |
| 오분류율 | ≤ 3% |  |  |
| 미판정률 | ≤ 5% |  |  |
| Macro F1 | ≥ 0.90 |  |  |

| 물리 피드백 지연 (P95) | ≤ 2.0초 |  |  |

## 2-2. 혼동행렬 (Confusion Matrix)

> 1부의 시행 로그를 집계하여 작성. 특히 "정지" 신호가 다른 신호로 오판정된 사례(치명 오분류)는 별도 강조.

*(표/이미지 삽입 예정)*

> **만드는 법:** "정답 클래스"를 행, "예측 클래스"를 열로 하는 표를 만들고, 각 칸에 해당하는 시도 건수를 채웁니다(파이썬이면 `sklearn.metrics.confusion_matrix` 사용 가능). 대각선(정답 클래스=예측 클래스)이 많을수록 좋은 모델입니다. "정지" 행에서 대각선이 아닌 칸에 숫자가 있으면 그게 치명 오분류이므로 빨간색 등으로 눈에 띄게 표시하세요.

## 2-3. 지연 분포

> 판정 지연, 물리 피드백 지연 각각의 분포(히스토그램) — P95 계산 근거 명시

*(그래프 삽입 예정)*

> **만드는 법:** 1부의 "판정지연(ms)"·"물리피드백지연(ms)" 열 값을 모아 히스토그램(막대그래프)을 그립니다. P95는 값을 오름차순 정렬했을 때 "하위 95% 지점"의 값입니다 — 예를 들어 100개 시도를 정렬했을 때 95번째로 작은 값. 엑셀의 `PERCENTILE` 함수나 파이썬 `numpy.percentile(data, 95)`로 계산 가능합니다.

> 데이터셋 명세서의 subject-wise split 검증: 팀원(train/val) 대비 외부인(test)의 정답률 차이 확인 — 과적합 여부 판단

| 대상 | 정답률 | 비고 |
| --- | --- | --- |
| 팀원 (train/val) |  |  |
| 외부인 (test) |  |  |

> **작성법:** 두 정답률의 차이가 크면(예: 팀원 98% vs 외부인 75%) 과적합이 실제로 발생했다는 뜻입니다. 이 경우 원인(데이터 다양성 부족 등)과 대응(추가 데이터 수집, 정규화 강화 등)을 함께 적으세요. 차이가 크지 않다면 subject-wise split이 잘 작동했다는 근거로 그대로 기재하면 됩니다.
